How to open and read a HAR file in your browser, offline

To read a HAR file without uploading it anywhere, open it in RequestFox, a browser extension for Chrome and Firefox. In History press Open file…, pick the .har file, then open it from the list. Every call is listed with its status, timing, headers and bodies, and the failed, slow, repeated and hidden-error calls are flagged. The file is read on your computer, and nothing is sent to us.

For RequestFox 2.5.0, checked 19 November 2026. Facts about browsers are from their own documentation, checked 20 November 2026; sources below.

Where do I get a HAR file?

  • Chrome: in the DevTools Network panel, press Export HAR (sanitized)… in the bar at the top of the panel [1].
  • Firefox: in the Network Monitor, right-click a request and choose Save All As HAR [2].
  • RequestFox: a session you recorded exports as HAR from the Export menu, and from History (its More menu).

A file someone sent you for a bug report works the same way.

How do I open a HAR file?

  1. Open History

    In RequestFox, press History in the top bar.

  2. Press Open file…

    Pick the .har file. Files up to 256 MB open. A dialog titled File opened says how many requests were loaded into History, and what was hidden (see below).

  3. Open it from the list

    The file is a session named after it, starting with "Imported:". Press its name to open it in the log, read-only. Your own recordings are untouched.

  4. Find the call you need

    Type in Search calls: a word matches the address, the method or the status, and filters such as status:>=400 or latency:>1000 narrow it down. Open a card to read its headers, body and timing.

  5. Take it further

    Press Report on the session for an HTML report, or open its More menu for CSV, JSON, a Postman collection and more. Compare to current sets it against what you are recording now.

A RequestFox session file (.requestfox or .json) opens the same way, with its flags and console log.

What does RequestFox flag in a HAR file?

The same things it flags in a live recording, read from the file:

  • calls that failed: a status of 400 or more, or a network error;
  • slow calls, over the limit set in Settings (Flag a call as slow after (ms));
  • repeated calls: the same request again within a short time;
  • errors inside a 200 OK, in GraphQL, JSON-RPC and SOAP responses;
  • streams that sent an error event.

Browsers' own preflight checks (the OPTIONS call before a cross-origin call) are not counted as slow or repeated.

Are the tokens in the file shown?

Not by default. While Hide passwords, tokens and card numbers in what is recorded is on in Settings, tokens, passwords and cookies in an opened file are hidden as it opens, and the File opened dialog lists what was hidden, by kind. Turn that setting off and the file opens as it is. To pass the file on without them, see how to clean a HAR file before you share it.

What does it not show?

  • A HAR holds what the Network panel held. It has no console log, so none is shown. A RequestFox session file does.
  • The Cookie header, Host, Connection, Content-Length and HTTP/2 pseudo-headers are left out when a HAR is read.
  • A file with no requests in it, or that is not a HAR or a session file, is refused with a message saying so.

Catch the API bugs the screen hides

RequestFox is a free browser extension that lets a manual tester test an API without writing code: press Start, use the app as a user would, watch the flags, and copy a bug report from the call that went wrong. A page can look fine while a call behind it failed, fired twice or returned an error inside a 200 OK. RequestFox flags those as they happen and ties each one to your click.

For RequestFox 2.5.0, checked 19 November 2026.

How to test an API without code

  1. Open the RequestFox side panel on the page you're testing and press Start.
  2. Use the app the way a user would. Every call is listed the moment it starts.
  3. Watch the flags on the calls. Press "Why is this flagged?" for the reason in plain words and a next step.
  4. On the call that went wrong, open More and choose Copy bug report, or open a GitHub or Linear issue from it (set up once in Settings).

What you will find that the screen does not show

  • Calls that failed quietly while the page kept a stale value.
  • The same request sent twice by one click (a double submit), or retried after a failure.
  • A GraphQL or JSON-RPC error inside a 200 OK.
  • A 401 caused by an expired token, said in words.
  • A response whose shape changed since earlier in the session.
  • JavaScript errors, next to the calls.

A worked example: an order that "worked"

Say you test a shop. You press Place order and the page shows a green "Order placed" message. In RequestFox, POST /api/orders carries the Failed flag and HTTP 500, and the card is tied to the click that sent it. Press "Why is this flagged?" and it says: "The server failed while answering (a 5xx status)." Its next step: check the server's logs for that moment, and press Replay to send the same request again and see whether it repeats. In a long session, type status:500 in the search box to list only the calls that failed that way.

Then choose Copy bug report from More on that call, or open the GitHub or Linear issue from it. The developer gets the call itself, with its status, instead of "the order sometimes fails". You didn't write code or open DevTools.

Bug reports nobody has to reproduce

Open a GitHub or Linear issue from a call with the repro filled in, or export the session as a self-contained HTML report or a HAR file to attach. Authorization headers, cookies and secret-shaped fields are redacted by default, so the evidence is safe to share as it is.

Test the edge cases without waiting for the backend

Make an endpoint fail, drag or return an empty list, and see what the page does. Calls you changed are labelled, so nobody files them as real bugs by mistake. How to mock an API response.

Make a manual check repeatable

Save the calls that matter, add pass/fail checks, chain them into a suite, and hand the suite to CI. How to run API checks in CI.

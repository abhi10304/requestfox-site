How to test an MCP server from your browser

In RequestFox, a browser extension for Chrome and Firefox, open Compose, set the body type to MCP server, type the server's address (it often ends in /mcp) and press Connect. RequestFox lists the server's tools, resources and prompts. Pick a tool, fill the form it builds from the tool's input schema, and press Call tool to read the response. The requests are plain JSON-RPC over HTTP, and RequestFox runs no AI model: it sends only what you pick.

For RequestFox 2.5.0, checked 19 November 2026. Facts about the MCP Inspector are from its own documentation, checked 20 November 2026; sources below.

How do I test an MCP server?

  1. Choose the MCP server body type

    Press Compose in the top bar, open the Body tab and set Body type to MCP server. The tester works over Streamable HTTP, with MCP 2026-07-28 servers and 2025 ones.

  2. Type the address and connect

    Type the server's address in the URL box. It needs to be an http:// or https:// address. Press Connect. The line under it says what RequestFox is asking, then which server you are connected to and which MCP version it speaks.

  3. Pick a tool, a resource or a prompt

    The three lists are Tools, Resources and Prompts, each headed with its count. A tool marked Read-only or Changes data says so. Press Refresh lists if the server's lists changed.

  4. Fill in the arguments

    Under Arguments RequestFox builds a form from the tool's input schema and marks each required field. Edit as JSON switches to raw JSON, and Edit as form back again.

  5. Call it and read the response

    Press Call tool (Read for a resource, Get prompt for a prompt). The badge says Result, Tool error (the tool ran and reported an error) or an error code from the server. If the tool has an output schema, RequestFox says whether the result matches it. The Messages list under the result shows everything that went over the wire.

Can I copy what was sent?

Yes. Under a result press Copy as request. The dialog shows the JSON-RPC request RequestFox sent for that call, with secrets hidden, and offers it as Copy as cURL or Copy as JSON. Paste it into a bug report, or run the cURL command to reproduce the call outside the browser.

What if it does not connect?

  • Nothing answers. Is the server running, and is the address right? RequestFox says the server did not answer. A 404 usually means the path: it often ends in /mcp.
  • The server wants a sign-in (HTTP 401). Press Sign in… to sign in with the server's own sign-in server, or set a token in the Auth tab. RequestFox asks before it goes to a sign-in server, and says at which step a sign-in stopped.
  • HTTP 403. Check the Auth tab. A server on your own computer may also refuse the browser's Origin header; allow it in the server.
  • You are offline, or RequestFox has no permission for the site. It says so; allow the site when the browser asks, then connect again.
  • An old server. If the server does not answer a POST, RequestFox tries the older HTTP+SSE transport (2024-11-05) before it gives up.

Should I use RequestFox or the MCP Inspector?

The MCP Inspector is the project's reference tool for testing and debugging MCP servers. It runs through npx on your computer, in a browser, on the command line or in a terminal, and it can launch a local server by its command [1]. It needs Node.js [1].

RequestFox is already in your browser, and it tests servers that answer over HTTP. It cannot start a stdio server: a stdio server is a program, and a browser cannot start one. Use the Inspector for that. For a server on a web address, the two do the same jobs; RequestFox keeps the call beside your other requests, environments and sign-ins.

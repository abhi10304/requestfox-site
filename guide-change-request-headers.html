How to change or add a request header on a site

Open Header & URL rules in RequestFox, a browser extension for Chrome and Firefox, choose Set a request header, type the part of the address it is for, the header's name and its value, and press Add rule. The rule changes the API calls of the tabs RequestFox records, while it records. To keep a header on with nothing recording, put the rule in a rule set for the sites you name and switch the set on. The same place removes a header, sets or removes a response header, and rewrites part of a URL.

For RequestFox 2.5.0, checked 15 November 2026.

How do I add a header to a site's requests?

  1. Open Header & URL rules

    In RequestFox, open Settings → Mocks & rules → Header & URL rules.

  2. Choose what the rule does

    Set a request header adds a header or replaces its value. The same list has Remove a request header, Set a response header, Remove a response header and Rewrite part of the URL.

  3. Say which calls it is for

    In URL contains, type part of the address, such as /api/. A rule applies on the sites you record; start it with * for every site, or begin with a site's name, such as api.example.com/v1/, for that site.

  4. Name the header and press Add rule

    Fill in the Header name, such as X-Debug, and its Value, then press Add rule. Each rule has its own switch, so you can turn one off without deleting it.

  5. Record, and the header goes with every matching call

    Press Start Recording and use the site. The rules in this list change the API calls (fetch and XHR) of the tabs RequestFox records, while it records, and only then.

How do I keep a header on all the time?

Use a rule set. Under Keep some rules on without recording, press New set, give it a name, the sites it is for (such as api.example.com, localhost) and its rules, one per line: header|X-Flag|beta sets a request header, removeheader|Name removes one, responseheader|Name|Value and removeresponseheader|Name do the same to the response, and rewrite|find|replace changes the address. Then switch it to Keep on.

The browser asks once to let RequestFox change requests on those sites. From then on the set changes page loads and API calls on those sites in every tab, recording or not, until you switch it off, and a chip under the top bar says which sets are on. A set is only ever on for the sites you name. Export saves your sets to one JSON file to share, and Import reads it back.

Can I bring my ModHeader profiles?

Yes. Import under Keep some rules on without recording reads a profile file exported from ModHeader as well as RequestFox's own export. The imported sets start switched off: check their sites, then turn them on. A value that looks like a secret, such as a token, is left out of an export; after an import, those rules stay off until you fill the value in.

What if the header does not show up?

  • Nothing is recording. The Header & URL rules list works while RequestFox records. To keep a header on without that, use a rule set.
  • The call is a page load, an image, a script or a stylesheet. The Header & URL rules list changes API calls (fetch and XHR) in the tabs you record. A rule set changes page loads too. Neither changes images, scripts or styles.
  • The address does not match. A rule with no site in it applies on the sites you record. Start it with *, or begin it with the site's name.
  • The browser refused the rule. RequestFox says so under the list and names the reason; the other rules stay on.
  • A set says Needs site access. Switch it on again and allow RequestFox on that site when the browser asks.

Can DevTools change a header?

Chrome's DevTools can override a response header locally, with DevTools open, through local overrides [1]. For a request header, or for a rule that stays on for a site in every tab, use a rule in RequestFox.

Sources

  1. Chrome for Developers, "Override web content and HTTP response headers locally". Checked 15 November 2026. developer.chrome.com

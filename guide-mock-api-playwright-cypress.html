How to mock an API for Playwright or Cypress tests

The mock itself lives in your test code: Playwright answers a request with page.route and route.fulfill [1], and Cypress with cy.intercept and a static response [2]. RequestFox, a browser extension for Chrome and Firefox, does not write those mocks for you. It helps around them: record the real call to get the exact response to copy into your mock, mock a call by hand in the browser while you build a screen, and export a recording as a Playwright or Cypress test that calls the real API and checks what came back.

For RequestFox 2.5.0, checked 19 November 2026. Facts about Playwright and Cypress are from their own documentation, checked 20 November 2026; sources below.

How do I mock an API in Playwright or Cypress?

  • Playwright: page.route() catches requests that match a URL pattern, and route.fulfill() answers them with data you supply. route.fetch() makes the real request so you can change its response first, and page.routeFromHAR() replays requests from a HAR file [1].
  • Cypress: cy.intercept() can spy on requests, stub their responses, or both. A static response with a statusCode, headers and body, or a fixture, is the stub [2].

Both run inside the test, so the mock is in your repository and runs in CI.

Where does RequestFox help?

A mock is only as good as the response behind it. Press Start Recording, use the page, and open the call's card: Response shows the real status, headers and body to copy into route.fulfill() or a Cypress fixture. For a bug that shows only on some responses, the failed and odd calls are already flagged. How to record API calls.

Can I mock a call in the browser, to build or test by hand?

  1. Record the call

    Press Start Recording and do what makes the call.

  2. Press Mock on the card

    Open the card and press Mock. Change the status or the body to an error, an empty list or a missing field.

  3. Press Mock it and reload

    Press Mock it and reload the page. It gets your response, and the card says Mocked.

This mock answers the page in your own browser, while RequestFox records the tab or keeps it on. It does not run inside a Playwright or Cypress run. Mock an API response has every step.

How do I export a Playwright or Cypress test from a recording?

  1. Record the flow

    Press Start Recording, use the app, press Stop.

  2. Choose the test code

    Press Export (bottom right) and, under Functional test code, choose Playwright test or Cypress test.

  3. Run the file

    The comment at the top of the file gives the command to run it.

The file has one test per recorded request. A Playwright test uses the request fixture and a Cypress test uses cy.request. Each test sends the request to the real API and checks the status that was recorded and the top-level shape of the response. A value that one response returns, such as an id or a token, is passed on to the requests after it. A token or other secret header is not written into the file: it becomes a named setting read from the environment, and the top of the file says which to set. These tests call the API for real; they do not mock it.

What does RequestFox not do here?

  • It does not generate page.route() or cy.intercept() code.
  • It does not mock inside your test run. Its mocks live in the extension, in your browser.
  • If you keep a HAR file in your repository for Playwright to replay, clean it of tokens first.

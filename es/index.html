Mira qué llamada a la API Falló.

Sin inicio de sesión, funciona sin conexión. RequestFox es un probador de API y monitor de red gratis, en un panel lateral para Chrome, Edge y Firefox. Graba cada llamada que hace tu app web, marca las que fallan en el momento en que ocurren y te deja repetirlas, simularlas y probarlas.

Dónde encaja RequestFox

Cada una de estas herramientas de pruebas de API es la indicada para algún trabajo. Elige RequestFox cuando pruebas una app web y quieres que sus problemas de API aparezcan solos, en el momento en que ocurren.

Qué herramienta para qué trabajo

  • Pruebas una app web y quieres que los problemas aparezcan solos

    RequestFox. Graba las llamadas mientras haces clic, marca lo que falló, tardó, se disparó dos veces o se rompió dentro de un 200 OK, y guarda cada sesión.

  • Ver en bruto todo lo que hace una carga de página

    El panel Red de DevTools. Viene en el navegador; tú filtras y lees. RequestFox frente a DevTools

  • Diseñar, documentar y compartir API en equipo

    Postman o Insomnia. RequestFox importa de los dos y exporta de vuelta a los dos. RequestFox frente a Postman · RequestFox frente a Insomnia

  • Solicitudes guardadas como archivos de texto en Git, junto al código

    Bruno. En Chrome, RequestFox también puede guardar una colección como archivos en una carpeta vinculada. RequestFox frente a Bruno

  • Un cliente web de código abierto que puedes alojar tú

    Hoppscotch. RequestFox no tiene nada que alojar: no hay servidor. RequestFox frente a Hoppscotch

Dónde se queda corto RequestFox

  • Ve lo que envía una pestaña del navegador. Las apps móviles y de escritorio necesitan un proxy como HTTP Toolkit, Proxyman o Charles.
  • Sin espacio de trabajo de equipo ni sincronización en la nube, a propósito. Comparte el trabajo como archivos: colecciones, sesiones, HAR e informes.
  • Los scripts solo se ejecutan en Chrome: Firefox no deja que las extensiones ejecuten código escrito en tiempo de ejecución.
  • Sin cliente nativo de gRPC ni MQTT (solo gRPC-Web y Connect).

Cada problema, dicho en palabras claras

Las llamadas se juzgan al terminar. Elige un aviso para leer lo que el panel te dice de él.

Aviso

POST /api/orders 500 412 ms

¿Por qué tiene este aviso?

El servidor falló al responder (estado 5xx).

Qué hacer: Mira los registros del servidor de ese momento; «Repetir» envía la misma solicitud otra vez para ver si vuelve a ocurrir.

GET /api/search?q=boots 200 3.1 s

¿Por qué tiene este aviso?

La respuesta tardó más que tu límite de lentitud.

Qué hacer: «Tiempos», en Detalles, muestra en qué se fue el tiempo; el límite está en Configuración.

POST /graphql 200 96 ms

¿Por qué tiene este aviso?

La respuesta dice que la llamada falló, aunque su estado HTTP es OK.

Qué hacer: Lee el error dentro de la respuesta: el estado por sí solo oculta este fallo.

GET /api/me 401 54 ms

¿Por qué tiene este aviso?

La llamada fue rechazada y el token que envió ya había caducado.

Qué hacer: Vuelve a iniciar sesión o renueva el token, y envía la llamada otra vez.

GET /api/cart 200 120 ms

¿Por qué tiene este aviso?

La forma de la respuesta (sus campos y tipos) no es la que esta llamada devolvía antes.

Qué hacer: Abre la diferencia de forma en la tarjeta para ver qué cambió.

GET /api/stock/42 503 230 ms

¿Por qué tiene este aviso?

Esta llamada falló en algunas sesiones grabadas y funcionó en otras.

Qué hacer: Compara una respuesta fallida con una correcta en el Historial.

Del aviso a la solución

01 Repetir

Repítela, o edítala antes

Vuelve a enviar cualquier llamada grabada tal como fue, o cámbiala en «Redactar». Entornos, {{variables}}, OAuth 2.0 con código de dispositivo, OAuth 1.0a, JWT Bearer y AWS Signature v4 vienen incluidos, y puedes tener varias solicitudes abiertas a la vez.

Guarda ejemplos y notas en solicitudes y colecciones. Un almacén de cookies que activas por sitio lleva un inicio de sesión a tus siguientes envíos, y el cliente WebSocket tiene un modo Socket.IO.

Cómo repetir y editar una solicitud

02 Simular

Simúlala, rómpela, hazla lenta

Abre una llamada y pulsa «Simular»: su estado y su cuerpo reales están ahí para cambiarlos. Pulsa «Simular» otra vez, recarga la página y la página recibe tu respuesta. Una regla también puede hacer que una llamada falle, vaya más lenta o se pause, sin tocar el backend. Los conjuntos de reglas y de simulaciones siguen activos cuando quieres.

En Chrome también puedes hacer más lenta toda la pestaña, o reescribir una solicitud o una respuesta con un script. Las llamadas que cambiaste llevan una etiqueta Simulada o Inyectada, para que nadie las confunda con errores reales.

Cómo simular una respuesta de API

03 Pruebas

Compruébala y ejecuta las mismas comprobaciones en CI

Añade comprobaciones a un endpoint: estado, tiempo, campos, cabeceras o un JSON Schema, y encadena solicitudes guardadas en suites. La herramienta de línea de comandos descargable las ejecuta en tu pipeline y hace fallar el build cuando una comprobación falla. También recibes consejos sobre caché y compresión, y una comprobación de que una respuesta sigue igual que la última vez.

Las colecciones entran desde Postman, Insomnia, Bruno, Hoppscotch y Thunder Client, OpenAPI 3, Swagger 2, WSDL, HAR y cURL. Vuelven a salir como colecciones de Postman, colecciones para Bruno, Insomnia y Hoppscotch, OpenAPI 3.0, una página de documentación de la API, código en 15 lenguajes, o scripts de Playwright, Cypress, k6, JMeter, Gatling y Locust.

Cómo ejecutar tus comprobaciones de API en CI

04 Herramientas de IA

Prueba tus herramientas de IA, sin IA dentro

RequestFox no ejecuta ningún modelo de IA. Prueba las herramientas de IA que construyes: «Redactar» se conecta a un servidor MCP y llama a sus herramientas, y una llamada a una API de modelo de lenguaje muestra el modelo, los recuentos de tokens que da la respuesta, el motivo de parada y el tiempo.

Con el control MCP activado (está desactivado por defecto), un agente de IA en tu propio ordenador puede grabar, repetir y simular a través de RequestFox. Cada envío y cada repetición esperan tu clic.

Preguntas

¿RequestFox es gratis?

Sí. RequestFox es gratis, y nuestra promesa está escrita aquí: nada que puedas usar gratis hoy pasará a ser de pago más adelante. No tiene anuncios, ni cuenta, ni plan de pago.

¿RequestFox envía mis datos a algún sitio?

No. Todo lo que RequestFox graba se queda en el almacenamiento de tu navegador, en tu dispositivo. No hay servidor de RequestFox, ni analítica, ni cuenta. Las cabeceras Authorization, las cookies y los campos con forma de secreto se ocultan por defecto en todo lo que RequestFox guarda, registra o exporta («Redactar» muestra la respuesta a tu propia solicitud tal como llegó; su lista de recientes guarda tus últimos 100 envíos, ocultos, en este dispositivo hasta que pulsas «Borrar»), y el acceso a los sitios solo se pide cuando pulsas «Iniciar grabación» o, para los sitios implicados, cuando envías desde «Redactar» o ejecutas una suite de pruebas mientras no se graba nada.

¿RequestFox usa IA?

No. RequestFox no ejecuta ningún modelo de IA. Puede probar las herramientas de IA que construyes: servidores MCP y las llamadas que una página hace a una API de modelo de lenguaje. Con el control MCP activado, que está desactivado por defecto, un agente de IA en tu propio ordenador puede manejarlo, y cada envío espera tu clic.

¿Hay una alternativa gratis a Postman que funcione en el navegador?

RequestFox es una extensión de navegador gratis que redacta y envía solicitudes con entornos, {{variables}}, ayudas de autenticación como OAuth 2.0 y colecciones guardadas, importa colecciones de Postman, Insomnia, Bruno, Hoppscotch y Thunder Client, y exporta colecciones de Postman y colecciones para Bruno, Insomnia y Hoppscotch. A diferencia de un cliente independiente, también graba las llamadas que tu app web hace de verdad. No tiene espacio de trabajo en la nube ni sincronización de equipo.

¿En qué se diferencia RequestFox del panel Red de DevTools?

DevTools muestra cada solicitud y te deja el juicio a ti. RequestFox marca las llamadas fallidas, lentas, duplicadas y reintentadas en el momento en que ocurren, vincula cada una al clic que la causó, comprueba tus reglas por endpoint y guarda cada sesión para que puedas comparar la ejecución de hoy con la de ayer. DevTools es mejor para una vista en bruto y en vivo de todo lo que carga una página.

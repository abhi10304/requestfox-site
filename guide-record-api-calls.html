How to record the HTTPS requests (API calls) a website makes

To see the API calls a page makes, open your browser's DevTools, choose Network and filter to Fetch/XHR (XHR in Firefox); nothing to install. To keep them, have the bad ones flagged, and replay or export them, use a browser extension such as RequestFox: install it, open the site, press Start (or Alt Shift S) and use the site as usual. Every fetch, XMLHttpRequest, WebSocket frame and server-sent event is listed the moment it starts.

For RequestFox 2.5.0, checked 19 November 2026.

First, the built-in way: the DevTools Network panel

You do not need an extension to see a page's API calls. In Chrome, open DevTools (F12), choose Network and click the Fetch/XHR filter. Right-click a request and choose Copy to copy it as cURL or as fetch, and tick Preserve log to keep requests across page loads [1]. In Firefox, the Network Monitor opens with Ctrl+Shift+E (Cmd+Opt+E on a Mac) [2]; its XHR button filters the list, and Copy as cURL and Copy as Fetch are in the right-click menu [3].

DevTools lists everything live but leaves the judging to you, and the list is gone when you close it. RequestFox adds the flags, the History and the export. RequestFox vs the DevTools Network panel.

Steps to record API calls in Chrome or Firefox

  1. Install RequestFox

    Add it from the Chrome Web Store or Firefox Add-ons. There is nothing to sign up for.

  2. Open the site you want to test

    Any normal web page works. Browser pages such as the extensions page, a new tab or the Web Store cannot be recorded; RequestFox says so if you try.

  3. Press Start

    Click the RequestFox icon to open the side panel (the sidebar in Firefox) and press Start Recording, or press Alt+Shift+S (Option+Shift+S on a Mac). The first time, the browser asks you to allow access to the site: allow it.

  4. Use the site as usual

    Click through the flow you are testing. Each call appears as it starts, tied to the click or form submit that caused it. To record a page's very first calls (sign-in, config, feature flags), tick "Reload the page to record its startup calls" before you press Start Recording.

  5. Read the flags

    Calls that failed, were slow, fired twice or broke inside a 200 OK are marked. Open one to see its headers, body, timing and the reason in plain words.

  6. Stop, and keep the evidence

    Press Stop. The session is kept in History to reopen and compare. Export it as an HTML report, HAR, CSV or JSON, or copy one call as code.

Find one call in a long recording

Type in the search box. Words each have to match, in any order, and tokens narrow the list:

  • status:500 or method:POST
  • host:api.example.com, or -host:cdn.example.com to leave a host out
  • path:/users/:id for every call to one endpoint, whatever the id

If nothing shows up

  • The list says to open a site first: you pressed Start on a browser page. Open the site, then press Start.
  • You chose not to allow access: press Start again and allow it. You can remove the access later in your browser's settings for the extension.
  • The list is empty while recording: the page has made no calls yet. Click something that loads data, or reload the page.
  • The shortcut does nothing: another extension may use it. Set it again at chrome://extensions/shortcuts (Firefox: about:addons, the gear, Manage Extension Shortcuts).

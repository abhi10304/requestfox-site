RequestFox vs Requestly: two browser extensions for working with API calls

RequestFox and Requestly are both browser extensions that work with the API calls a web app makes. Pick Requestly if you want to intercept and rewrite traffic with rules, in many browsers and, with its desktop app, beyond the browser. Pick RequestFox if you want to record the calls a web app makes, have the broken ones flagged for you, and test them, with no account and nothing sent to us. They do different jobs, and some people run both.

Facts about Requestly are from its own pages, checked 4 November 2026; sources below. Written by the RequestFox team, for RequestFox 2.5.0.

Where is Requestly stronger?

  • A long list of rule types that stay on while you browse: change headers or bodies, redirect to another environment, map a URL to a local file, insert your own script or style into a page [1].
  • More browsers: its extension lists Chrome, Firefox, Edge, Brave, Arc, Vivaldi and Opera [1].
  • Traffic from outside the browser, through its desktop app: phones, simulators, desktop apps, Node.js and the terminal [1].
  • Team Workspaces that sync rules between the extension and the desktop app [1].
  • A wider product: a Git-native API client with collections, scripts and tests, sold in team plans [4][5].

Where is RequestFox different?

  • It judges the calls. Failed, slow, duplicate and retried requests, N+1 bursts, GraphQL errors in a 200, expired tokens and changed shapes are flagged as they happen, each tied to the click that caused it.
  • It keeps every session, so you can compare today's run with yesterday's, and turns a recording into checks you can run in CI.
  • No account for anything, and nothing is sent to us.
  • Mock and fault rules label the calls they change, so nobody files a mocked response as a bug.

Where RequestFox falls short, so you're not surprised:

  • It runs in Chrome, Edge and Firefox, and only sees what a browser tab sends. Mobile and desktop apps need a proxy tool such as HTTP Toolkit, Proxyman or Charles.
  • It has no rule that puts script or style into a page.
  • There's no team workspace or cloud sync, by design. You share work as files.
  • It is free. Its code is MIT-licensed and ships readable inside the extension, so you can check it yourself; the source repository is not public.

Can I use both?

Yes. They're separate extensions with separate jobs. Record and test a flow in RequestFox to see which calls fail and why, and keep always-on rewrites, like sending a request to a staging server, in Requestly. How to mock an API response in RequestFox.

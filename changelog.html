Changelog

What changed in the newest RequestFox releases, newest first. This page is built from the project's own changelog, so it says exactly what shipped. The current version is 2.3.0.

Releases

Newest first. The browser updates the extension by itself.

2.3.0 2 November 2026

Shortcuts moved

  • Shortcuts are now Alt+Shift+S (start or stop recording) and Alt+Shift+M (switch between Full, Background and Mini) — Option+Shift on a Mac — so they no longer take Chrome's own Reload key. Help → Keyboard shortcuts lists them.
  • Alt+Shift+S, not Alt+Shift+R: Chrome keeps Alt+Shift+R for itself, so on a new install it left the recording shortcut "Not set" and the key did nothing until you set it by hand in chrome://extensions/shortcuts.
  • Alt+Shift+S opens the panel again: it used to wait before opening it, and the browser only lets a shortcut open the panel straight away, so nothing happened. The same press starts recording too, panel open or not; before site access is ever allowed, the panel says in one line to press Start once. Start on a browser page (chrome://extensions, a new tab, the Web Store) says to open the site first, instead of recording a page that can never show a call. Alt+Shift+M pressed right after the browser woke the extension no longer resets the other settings.

Getting around

  • The RequestFox logo and name in the top bar are Home: a click closes the open panel, leaves a past session and shows the newest request. Esc closes the open panel too, even from a field inside it, and focus goes back to the button that opened it, with the log where you left it.
  • The top bar shows which panel is open: its icon is highlighted, or More when that icon is folded into More. A panel's name, ? and × stay at its top while it scrolls.
  • Enter in Compose's address field sends. Enter in a session name, a new suite's name or the Mini popup's session name presses its button.
  • The Mini popup's logo opens the full panel, and its dot shows only while recording.
  • Help names each panel's walkthrough as a tour ("History tour"), so it is no longer mistaken for the panel itself, and the idle screen stops offering the tour once you have seen it.
  • A jump from the Timeline or an alert lands on its request card, with focus on it.
  • Cancel on the site-access explanation just cancels, with no second dialog.

Auth: more ways to sign in

  • OAuth profiles have a Sign-in method: browser sign-in (as before), Client credentials (no sign-in, the token is asked for by itself and again before it runs out), Refresh token, and Password (marked legacy). A server that says no gets a plain sentence with one next step (invalid_client, invalid_grant).
  • Paste an OpenID Connect issuer and "Fill from issuer" fills the endpoints; "ID token claims" shows what is inside an id_token (never its signature).
  • Compose's Auth type has AWS Signature v4 (region and service read from the host; keys as secret variables) and an HMAC signature preset. Saved requests, suites, the CLI and the CI export sign the same way; the keys leave the export as environment variables.
  • A GET or HEAD with a body typed says it sends no body.
  • A token or authorization address that starts with http:// is now refused (the secret would travel unprotected): use https. Only localhost may stay on http. Profiles saved before this with an http address show the plain message at Get token; edit the address to fix it.
  • Two sends that need a token renewed at the same moment now share one renewal, so a rotating refresh token is not spent twice.
  • Params, Headers and Form fields rows have a small checkbox: untick it and the row is dimmed and not sent (it stays in saved requests, left out of code and the CLI).
  • Compose's Auth type (and a collection's or folder's auth) has OAuth 1.0a: HMAC-SHA1, HMAC-SHA256, HMAC-SHA512, RSA-SHA1, RSA-SHA256, RSA-SHA512, and PLAINTEXT (sent only over https or to this computer). The request is signed as it is sent, after {{variables}}; realm, callback, verifier and "send the signature in the query string" are under More.
  • JWT Bearer makes and signs a new token on every send: HS256, HS384, HS512, RS256, RS384, RS512, ES256 and ES384, with claims, Expires in, iat, a key ID and a base64 secret. Another algorithm, or "none", is refused with a plain sentence. A 401 that looks like a clock difference says to check the clock.
  • OAuth 1.0a and JWT keys are secret fields: kept out of Export workspace, folder files and Copy as code. Suites, the CLI and the CI export sign the same way (the keys leave the export as environment variables), and a Postman import or export keeps both, naming what it could not bring over.

Recording

  • A page's very first calls, made before the recording has fully started, are captured too, and Firefox now loads the capture before the page's own scripts, so its startup calls are no longer missed there.
  • A call shows in the log the moment it starts, as a quiet "…" card that turns SLOW live; its finished card replaces it. Switching tabs no longer drops these cards, and the last one expiring brings the empty list's next step back.
  • Streams (server-sent events, NDJSON, token streams) are captured: their first 64 KB is kept. A stream that stays open says "Streaming…" instead of turning SLOW, and keeps that first part until it closes — even if the browser restarts the extension's background worker in between.
  • Failed calls say what went wrong in plain words (the raw code stays in the tooltip and in exports), and a successful call with no body says why. The in-page alert and the desktop notification use the same words now, never "net::ERR_FAILED", and the panel's own sends (Compose, a saved request, a suite step, Replay) raise neither: the panel reports them.
  • WebSocket frames are no longer cut short, duplicates are counted per tab, and a multipart form is replayed as form fields.
  • Numbers and units follow the panel's language and read right in Arabic; the timeline waterfall has a ruler.
  • Search takes host:api.example.com, and a "-" before any word or token leaves those requests out (-host:cdn.example.com, -status:200), as in DevTools. The search box's tooltip shows how.
  • Words separated by spaces each have to match, in any order: "users orders" finds /users/7/orders.
  • Calls to the same endpoint are counted as one: /users/1 and /users/2 are /users/:id (numbers, UUIDs, hashes, ids like ord_445566, dates), and GraphQL calls are told apart by their operation, JSON-RPC calls by their method. Performance, the Timeline, Heaviest endpoints, the test plan, rate limits, Top Issues, N+1, History's compare, the report and the exports all group the same way. A click on such a row filters the log with path:/users/:id, which you can also type in the search box.
  • A changed answer (SCHEMA CHANGED) is found up to 5 levels deep and inside lists, and stays quiet about fields that are optional or can be null. Your own sends (Compose, saved requests, suites, Replay from the extension) are checked against their own earlier answers too.
  • N+1 for an operation with no id in its path needs 5 calls within a second, so search-as-you-type is no longer flagged.
  • A card flagged as a repeat has "Stop flagging repeats" in its ··· More menu: repeats of that endpoint (every id) are no longer flagged, counted or alerted. The dialog that says so has Undo, and Settings → Noise filters lists the endpoints, each with "Flag again".
  • Captured GraphQL calls to an endpoint with a schema kept are checked against it: SCHEMA MISMATCH and the reason on the card, every problem under Details. A persisted query that sends only its hash shows its text once a call has sent the two together.
  • A call's security findings are listed under Details, not only in the SECURITY badge's tooltip, and a finding that is only advice gets a calmer badge. New passive checks: a token in a URL query, an answer with a login that shared caches may keep, a JWT with alg "none", and card numbers or many emails or phone numbers in an answer. Masked or redacted values and ids never count.

JSON answers

  • A JSON answer can be read as a tree: press Tree, in a log card or in Compose (the choice is remembered). It opens at most 8 levels by itself, shows long lists a page at a time, and has a filter once there are more than 25 values.
  • Click any value (or right-click it) for Copy value, Copy path, Check this value (a pass/fail check on later answers) and Save as variable (an environment variable for {{name}}). The first tree you open says so in one line. A value hidden by "Redact sensitive data" is never saved as a variable; its check only asks that it is there.
  • Numbers keep every digit as sent: a 64-bit id like 12345678901234567890 is not rounded, and Copy value copies it exactly.
  • Compose's body editor says where and why the JSON breaks while you type, in the panel's language ("Not valid JSON: line 4, column 12 — a comma is missing here"), with "Go to line 4". GraphQL variables are checked too. It never blocks Send.

Replay and breakpoints

  • Replay keeps the real Authorization and Cookie values when the browser restarts the background worker, and refuses with a clear reason rather than sending "*REDACTED*".
  • A breakpoint nobody answers no longer hangs the page: the call goes out unedited and its card says BREAKPOINT SKIPPED. Closing the panel with a breakpoint dialog still open now does the same at once, instead of holding the page's call for up to ten minutes. With the side panel and the DevTools panel both open, closing one leaves the other's dialog in charge: your edit is no longer lost.
  • Replay refuses, with a reason, a request whose stored body had a value hidden by "Redact sensitive data" or was cut at the capture limit, instead of sending "*REDACTED*" or half a body; Edit & Replay still sends.
  • Replay of a call to another site that the page's CORS rules refuse (for example an analytics beacon that allows any site but no cookies) is sent again from the extension by itself, without the page's cookies, and says so under the card; its new card is marked FROM EXTENSION. Any Replay failure now says what went wrong in plain words, with a next step, instead of "TypeError: Failed to fetch".
  • Replay sequence says how many of its calls change data (POST, PUT, PATCH or DELETE) and asks in the red danger style before it sends them again.

History and past sessions

  • Export file names are short and say what they are: the site (or the name you typed) and when the recording started, once, in your local time — requestfox-github.com-2026-10-23-2108.har, not the session name with its date plus a second, ISO timestamp. The same for the report, CSV, JSON, Postman, OpenAPI, test scripts, settings and workspace files.
  • The Performance panel fills in live while recording (at most once a second) instead of only after Stop, and with nothing captured yet it says "Recording — stats appear as requests come in." No panel tells you to start a recording while one is on any more: the empty log, History's "Compare to current" and a suite's send error say what to do instead, and with a past session open during a recording, Compose and Suites still know it is recording.
  • Open a past session in the log, read-only, and go back with "Back to live" or Esc. The recording keeps going meanwhile, and a suite step, a post-response script or the Compose preview waiting on a live response still finishes while the past session is on screen. Switching tabs no longer closes it; only a new recording does, and a screen reader hears it. Deleting the session you are looking at takes you back to the live log. Going back to live, opening a past session and starting a new recording show the newest request at the top, instead of keeping the place you had scrolled to.
  • A past or opened session remembers the page it was recorded on, so its bug report and HTML report name it; session JSON and HAR files carry it.
  • Bug reports start with the page the recording started on, the time, the browser and the session, and GitHub and Linear issue links stay short.
  • A past session can be saved as JSON or OpenAPI, and a RequestFox session file opens again with Open file…; a failed call in a HAR stays failed.
  • Delete asks first, History search results work from the keyboard, compare lists say how many rows they leave out, and a session that cannot be saved to History now raises an alert.
  • Pinned sessions come first in History, and every card's time uses one clock, in the panel's language.
  • Past sessions keep every body as it was captured, and their screenshots (before: the first 20,000 characters of each body and no screenshots). Opening one, and every export from History, uses the full copy. History keeps up to 50 unpinned sessions within 512 MB (or half of what the browser allows, if that is less); pinned sessions always stay. If the browser refuses the full copy, History keeps a shorter one and says so.
  • One line under History says how much space it uses on this device, with Clear old sessions: it says how many sessions go and keeps the pinned ones unless you tick "Also delete pinned sessions". It replaces Clear history, which deleted pinned sessions too.
  • History's compare boxes show only when there are two sessions to compare, under one line that says what they do, and a session's name looks like a link, since a click on it opens the session.
  • Open file… in History opens a session JSON (Export → JSON; .json or .requestfox), like a HAR, with its checks, issues and screenshots, for Report, CSV and Compare.

Compose and collections

  • Compose no longer needs a recording. With nothing recording, Send (in Compose or on a saved request) goes from the extension itself, without any page's cookies: the browser asks once for that one site (no prompt if you already allowed it at Start), and the answer shows in Compose. These sends stay out of the log, History and exports. While recording, Compose still sends through the page you test, as before.
  • Test suites no longer need a recording either. With nothing recording, Run sends every step from the extension, without any page's cookies: the Run click asks once for the sites the steps call, and a declined prompt says so under the suite instead of failing each step.
  • A calmer Compose: fewer controls when it opens, room in a 300 px sidebar (the environment list moves under the title), real labels, and a readable response — indented, with "Headers (1)" and a note when it is cut.
  • Slow sends are not cut off at 20 s and can be cancelled; a screen reader hears "Sending…" once, not every second.
  • Imports are saved as collections; collections and folders can be renamed, moved and deleted; one "Save to collection" dialog; Copy as code for a composed or saved request. Extra actions sit behind one "··· More" button in Compose, on saved requests and on collections.
  • {{variables}} in auth fields are filled in first, pasted curl commands read more flags, Postman imports keep inherited auth, and saving an environment never overwrites another one.
  • When the page can't reach an API on another origin (often CORS), Compose offers Send from the extension instead: RequestFox sends the same request itself, using the site access you allowed at Start, without the page's cookies, and marks it FROM EXTENSION. Replay on that card sends it the same way, the host is remembered until the browser closes, and the card names any typed header the browser does not let an extension send (Cookie, Origin…).
  • Secret variables: an environment can keep a value encrypted in the vault, masked, and never in an environment export or Copy as code.
  • Postman-style path variables (/users/:id) get their own rows under Params.
  • Importing a collection you already have asks: Replace or Keep both.
  • Copy as code refuses a {{variable}} the environment doesn't set, the way Send does.
  • Choose file… is a quiet button with the file's name beside it.
  • Compose shows the answer to your own send as it came; one line says the saved copy and exports hide values that look like secrets. A path variable's value is encoded as one path segment.
  • Recent: Compose keeps your last 100 sends from Compose and saved requests, recording or not, with their answers — on this device and redacted. The quiet Recent link lists them: filter them, reopen one with its whole form and answer, or Clear them. A saved request's send reopens tied to it ("From <collection> — Send uses its settings · Unlink").
  • Collection and folder settings (Collection settings… or Folder settings… in the ··· menu): variables, a base URL, headers and auth that every request inside uses. A folder's settings win over its collection's, a request's own auth wins over both, and the active environment wins over collection variables. Send, Copy as code, suites and the CI export all use them. Moving a request or deleting a folder says first how many requests it changes, and saving "No auth" into a collection with auth asks which you mean.
  • Postman import keeps {{variables}} as written, the collection's variables and auth (a folder's auth too), and Postman's secret variables stay secret. Simple pm.test checks (status, time, a header, a JSON field) become pass/fail checks on that request, and pm.environment.set from the answer becomes a chaining row. Other scripts are listed in a short import summary and kept as they were. Export to Postman… (a collection's ··· menu) gives the collection back with its variables, auth, folders and scripts.
  • Chaining can take a value from a response header, a cookie or a regex, not only from the JSON body. A value that is an object or a list is saved as JSON, not "[object Object]".
  • Sends from Compose, a saved request, a suite or a script run in the panel itself and are no longer cut off after 30 seconds: a slow answer is waited for, and Cancel stops it. Replay of a card sent from the extension goes the same way. If the panel closes before the answer comes, Recent keeps the send and says the request may still have reached the server.
  • A streaming answer (server-sent events, NDJSON, a language model's token stream) reads as one row per event, live, with "Events: N" and Stop, which keeps the events so far. A token stream also shows its text joined up, and a stream's card in the log uses the same rows.
  • A send from the extension says where its time went (DNS, connect, TLS, wait, download) behind a quiet Timing link, or says plainly that timing isn't available for it.
  • An image, PDF or protobuf answer to a send from the extension is kept as its bytes: an image shows as a preview, and Save response saves the real file under the server's file name.
  • gRPC-web, Connect and protobuf answers read as fields without a schema, with the gRPC status as a badge ("gRPC NOT_FOUND" is an error).
  • The WebSocket client has an optional subprotocol, "Reconnect if it drops" (five tries, then it stops), saved messages ("Forget saved messages" asks first) and a filter once its log grows long.
  • Socket.IO: the WebSocket/SSE panel reads a page's own Socket.IO traffic (v2 to v4) as events: event(args) lines, acks, namespaces and binary attachments, with pings hidden and counted and a Raw frames switch.
  • The WebSocket client has a Socket.IO mode that speaks v3 and v4 over the browser's WebSocket, without long-polling (a v2 server is named as such): path, namespace and a JSON auth payload; emit an event with JSON arguments and an optional ack, shown with its time; show only some events; pings answered and counted. Every failure says what happened and what to do. A Socket.IO request can be saved to a collection (its auth payload is a secret field) and opened again; it is not a suite step.
  • In Firefox the panel reaches your own ws:// servers and plain http:// servers on your network; Firefox had turned them into wss:// and https://.
  • After a send, one quiet line may offer the next step, from what just happened: save a token from a sign-in answer as {{token}}, add auth after a 401 (or a 403 that asks you to sign in), use a {{variable}} for a host you keep sending to, edit a check that failed, or move a secret header kept in a saved request into a secret variable. After a suite run, steps that pass on any answer below 400 get "Check each one's status". One click, with Undo; × is "Not now", a second × turns that kind off, and Settings shows turned-off suggestions again. Only one such line shows in the panel at a time.
  • Typing {{ in Headers, Params, form fields and the Auth fields lists your variables.
  • Checks on this request (Compose → Advanced): a saved request's own checks in plain words, with Edit and Delete (with Undo).
  • GraphQL that knows the schema: with the GraphQL body type, one line says "Schema: not loaded · Load". Load asks the endpoint (introspection), and Paste SDL… takes a schema file or an introspection answer; it is kept in this browser, per endpoint, with Reload and Remove (with Undo). The query box then suggests fields, arguments and enum values (Ctrl+Space or Alt+Down; Enter inserts), names a problem under it ("Did you mean price?") with Go to line, and Docs searches the schema. When a load fails, the line says why and the one next step (sign in, paste the SDL instead).
  • Link a folder… (Import & export, in Chrome) keeps your saved requests, environments, suites, checks and rules as plain files in a folder you pick, one readable file each, so git can track them. Changes are saved there as you work. After a git pull the bar says the folder changed, and Reload from folder brings the changes in, keeping the edits you made here. Passwords, tokens and keys RequestFox recognises stay on this device as {{placeholders}} in the files. A pull's header rules and URL rewrites arrive switched off, and its scripts are asked about first. A file RequestFox cannot read is left in the folder as it is, and a folder with other people's files is not linked over them.
  • Save as example under Compose's answer keeps that answer (status, headers, body) on the saved request; Examples (n)… in its ··· menu lists them, shows one, compares it with the latest answer (status, content type, JSON shape, headers that came or went), renames it, and deletes it with Undo. Cookies are never kept in an example.
  • Notes… on a saved request, a collection or a folder keeps plain text for a teammate; it shows as one quiet line under the name, and search finds it.
  • Examples and notes go with the request in exports and folder files (the secret scrub covers example bodies), and to and from Postman as saved responses and descriptions.

Settings, checks and suites

  • Pass/fail checks and header/URL rules are lists, each with an on/off switch and a remove button; the text box is a quiet "Edit checks as text" or "Edit rules as text" link.
  • Settings names say what they hold; mock and fault rules open with one line and short labels; Arabic keeps URL patterns the right way round.
  • Suites show translated errors and say why a step failed. The command-line tool refuses bad flags, answers --help and times out; rf.log() output shows under Compose.
  • Edit a saved check or header rule in place, and the comparison menu speaks words ("contains", "does not exist").
  • A suite step sends the saved request's Auth tab, as its own Send does, and a step to a host you chose Send from the extension instead for goes that way too.
  • The command-line tool says when checks are switched off or match nothing, stops before any request when a {{env:NAME}} it needs isn't set (and names it), and a diff with no baseline exits 2.
  • The security probe is called an OPTIONS check, and a clean result no longer claims CORS is fine.
  • Performance is calmer: Rate limits and Heaviest endpoints are closed rows you open when you need them, and a 300 px sidebar shows four tiles.
  • Checks and chaining read one path language: data.items[-1].id, items[*].price, filters such as items[?(@.price > 10)], .. and length(). A check on a list holds only when every item passes, and an empty list fails it.
  • The JSON Schema check understands much more of JSON Schema ($ref, allOf/anyOf/oneOf, if/then/else, formats and more) and never passes what it did not check: a keyword it does not support is listed as "not checked" and the check fails.
  • A check that cannot run marks that request's checks as failed, instead of losing the request.
  • Link an OpenAPI spec as the contract: an OpenAPI import links it, and Settings → Pass/fail checks → Contract changes it or turns it off. While a spec is linked, a call that breaks it shows SPEC MISMATCH with one line of reason, a call the spec does not have shows NOT IN SPEC, and Details lists every problem and what could not be checked. Calls to other sites (analytics, fonts) are never judged, and what RequestFox cannot check is "not checked", never a pass. With no spec linked nothing new shows.
  • Top Issues shows "Spec coverage: 34 of 52 operations seen"; a click lists the operations not called yet. The HTML report gets a Contract section, and Copy bug report a Contract line.
  • When a spec names no host and calls to a host on another site match several of its operations, one line asks "Check calls to <host> against this spec?": Check them (with Undo) or Not now, which is remembered. Settings lists the hosts added this way, each with "Stop checking".
  • A card can carry a quiet Advice badge, only for the site's own calls and local servers: a JSON or text answer sent without compression (with what gzip measured it would save, worked out in the browser), or the very same answer downloaded again with nothing a cache could use (no ETag, Last-Modified or max-age), with what a cache would have saved. Details has the fix in one line. It is advice, never an error.
  • A new check, "Same answer as last time" (Settings → Pass/fail checks, or one switch on a test suite), compares each answer with the last one for the same request. Clock times, random ids, tokens, nonces and the order of lists of records are left out on their own; you can name more paths to ignore. A changed card lists each changed value, was and now, and has "Use this answer from now on". Kept answers never hold a token, key, password, cookie or session id RequestFox recognises.
  • In the CLI the same check keeps each answer in requestfox-snapshots/ (--snapshots <dir> to choose); --update-snapshots takes the new answers, and in CI (the CI variable, or --ci) a missing saved answer fails.

Scripts

  • Pre-request and post-response scripts get rf.test("name", fn) and rf.expect(…) (Jest and Chai words), can await, and have rf.json(path), rf.getVariable, rf.crypto (SHA, HMAC, base64, UUID) and rf.sendRequest (up to 20 per run, each one logged). Their tests show on the request's card, in a suite's result and in Compose ("Script checks: 2 of 3 passed."). A script that runs too long is stopped, and the panel stays usable. Scripts run in Chrome; Firefox still refuses them, and chaining rows and checks do the same work there without code.
  • A pre-request script's changes to the request are sent; in Chrome they were lost.
  • Importing a collection with scripts warns that a script can also send requests of its own to any server. A regex longer than 200 characters is refused, with the reason.
  • The script boxes have Snippets: ready-made scripts with a comment that says why (save a token, refresh it when it runs out, check status, time and a field, sign with HMAC, add a request id and time). Typing rf. lists what scripts can use, each with a one-line note.
  • Problems show while you type, with their line and column: a text, bracket or comment never closed, a missing await, {{name}} typed inside a script, a secret typed into it, context.response in a pre-request script, and console.log. A Postman pm.* line gets its rf.* twin with Fix, or Fix all Postman lines at once.
  • A script that only saves values or checks the answer can become code-free Chaining rows and checks with Convert (with Undo); they run in Firefox too, where scripts can't. "Good habits for scripts" sums up the rest. Post-response scripts can read context.response.duration, in the panel and the CLI.

Command-line tool and CI

  • A suite's ··· menu offers Export as CI config again. Its dialog has Download the CLI: requestfox-ci.mjs, one file that ships inside the extension and runs with Node 18 or newer, with nothing to install (node requestfox-ci.mjs assert --config requestfox.config.json).
  • The CLI runs a suite the way the panel does: chaining (body, header, cookie, regex), saved auth, path variables, collection and folder settings, checks and scripts. A step whose {{token}} was never saved is not sent, and the run names the step that failed.
  • The export keeps typed-in secrets out of the file: a secret-looking value in a body, a query or a header becomes {{env:NAME}}, and the run stops before any request when that variable is not set. The dialog counts the requests, and the pass/fail checks when there are any.
  • conform --spec openapi.yaml --session session.json checks a recorded session (the extension's JSON export or a HAR file) against an OpenAPI 3 or Swagger 2 spec with the panel's own check: a line per call, the coverage and the operations not called yet; exit 1 on a mismatch. It has --reporter junit, --min-coverage and --strict, and --spec on assert and diff checks the CLI's own sends the same way.
  • "securityHeuristics": true in a CI config adds the side panel's newer security checks; off by default, so a suite that passed before still passes.
  • run <folder> runs the suites of a linked workspace folder (or a workspace export) with --suite, --env and --var; a folder with scripts needs --allow-scripts, as they are code. mock --spec api.yaml or mock --session captured.json starts a local mock server on 127.0.0.1.
  • mock --workspace <folder or file> answers each saved request's path with its first 2xx example; Prefer: example=<name>, Prefer: code=404 or Postman's x-mock-response-name / x-mock-response-code pick another. conform --spec api.yaml --workspace <folder> checks every example against the spec.
  • assert, diff, loadtest and run take --cert and --key (a client certificate), --ca (a private CA), --proxy and --insecure (staging only).
  • JUnit results carry each request's time and count errors apart from failures; a step that did not run is marked skipped.
  • requestfox-ci probe --spec api.yaml --base http://localhost:3000 makes test cases from an OpenAPI or Swagger spec and sends them: wrong types, missing required fields, values out of range or outside the enum, extra properties, malformed and oversize bodies must be refused with a 4xx (not accepted, not a 5xx), and an operation that needs sign-in must refuse a call with no or a wrong credential. Valid calls built from the examples must not fail and must match the spec. Each failure shows the request, a curl line and why, with every --header value shown as ***; --junit and --json for CI. Careful by default: this computer only unless --allow-remote, 5 requests a second, GET, HEAD and OPTIONS only unless --include-unsafe, at most 200 cases, the same cases for the same --seed, --dry-run to see them first.
  • mock --spec: Prefer: dynamic=true and the new --dynamic now make a different, schema-valid answer on each call (it used to be the same placeholder every time), and --seed repeats them. Prefer: example=name with a name the spec does not have answers a 500 that lists the names it has, as in Prism, instead of quietly sending the default.
  • YAML specs: a list item written as a flow mapping (- { name: limit, in: query }) is read as one mapping. It used to become a key named { name, so the parameters of a spec written that way were lost in the panel's import, conform, mock and probe.

Look

  • A new fox: our own one-colour fox mark, with "Request" and "Fox" in two colours, in the top bar, the Mini popup, the first-run splash, the empty log and the HTML report. The toolbar, DevTools and store icons are the same fox, with a red dot while recording.
  • An open card's views (Details, Request, Response) look like tabs; Replay and ··· More are plain actions at the end of the row.

Privacy

  • The page a recording starts on is redacted like every request address: a token in its query or #fragment (a magic link, a reset link, an OAuth callback) no longer reaches a report, a HAR, a bug report or an issue link.
  • Exporting settings or a workspace leaves secrets out (the token vault, client secrets, saved credentials), and importing cannot replace them.
  • Scripts run in a sandbox that can no longer navigate away.
  • One privacy policy, the same in every copy, that matches what the code does. RequestFox asks for one permission fewer (the unused activeTab).
  • The OAuth vault hint says what really happens: the passphrase is asked for again after the extension has been idle for a while.
  • Send from the extension instead goes only after your click, never with the page's cookies, and its answer is redacted like any captured body; the privacy policy says so.
  • A secret variable's value is redacted wherever it shows up in what a send captured: a URL path, any header, a body.
  • Redaction also catches S3 presigned signatures, Google API keys (key=), sig=, otp= and an OAuth code= in addresses and form bodies.
  • A field that is just a web address is no longer hidden because of its name: GitHub's "authorizations_url" or a sign-in server's "token_endpoint" show as they are. An address that carries a secret (a password, a secret-named query key, a token in its path) is still hidden.
  • Redaction also hides a PKCE code_verifier and a private_key, and no longer hides "author". The policy says a site chosen for Send from the extension stays chosen until the browser closes, and the Firefox reviewer notes explain the extension's own send.
  • Recent keeps the last 100 sends with their answers on this device, redacted, until you Clear them; a token or password typed in the Auth tab is never kept. The privacy policy, the FAQ and the Firefox reviewer notes say so.
  • Past sessions keep their full bodies and screenshots in the browser's own storage on this device; Delete and Clear old sessions remove them.
  • The CI export keeps typed-in secrets out of the file, the CLI runs scripts without your computer's environment variables, and a script's test results are stored without the values redaction hid. An export without credentials also leaves out the secrets in collection and folder settings.
  • Saved WebSocket messages stay on this device until you forget them; the privacy policy lists them.

  • "Running on Chrome" and the "Built by AJ" signature moved from the footer to the bottom of the Help menu.

What other API tools had, now here too

  • Expired tokens explained. A 401/403 sent with a Bearer JWT that had already expired gets a "Token expired" badge and a line saying how long before the call it ran out. Details shows any Bearer JWT's algorithm, issuer, audience, issue and expiry times against the call. It's read before redaction and keeps only those fields — never the subject, other claims or the signature.
  • N+1 detection. One endpoint called for id after id (/items/1, /items/2, … numbers, UUIDs or long hex ids) five or more times within 3 seconds shows as an "N+1" chip in the problems row; a click filters the log to it. The row is now called "Repeated problems".
  • Unset variables caught before sending. A {{name}} left in Compose's URL or headers after the environment is applied stops the send and names the variable and the environment, instead of going out as the literal text (a body may carry {{…}} on purpose, so it's left alone).
  • Format for Compose's JSON body: re-indents it with {{variables}} left exactly as written, and a body that looks like JSON but isn't says "Not valid JSON: …" under the box as you type.
  • Status pills name their code on hover: "404 Not Found".
  • Copy as code in 15 languages, adding C# (HttpClient), PHP (cURL), Ruby (Net::HTTP), Swift (URLSession), Kotlin (OkHttp) and Rust (reqwest), each with its own quoting: Kotlin's $, Swift/Rust \u{…}, PHP/Ruby single quotes (double-quoted with escapes when the text holds a control character), and C#'s rule that U+2028 can't sit raw in a string — the Rust and C# literals were compiled and checked byte for byte. Copy as code also wraps long lines instead of hiding them off to the side.
  • Right to left: the recording bar's separator and the "Triggered by" line read in the right order.

Calmer, easier to scan

  • Request cards lead with what the call was and whether it worked — method, path, status on the first line; the reason it was flagged, the time, duration and host on a quieter second line. Durations read "210 ms" / "4.2 s".
  • Colour only where something needs a look: a flagged request gets a stripe down its edge, a clean one doesn't, and the whole-card pink/amber tints are gone. Counter tiles stay neutral and their number turns red/amber only once there's something in it.
  • Body toggles (Headers, Response, …) keep their label and show a pressed look when open, so the action row no longer re-wraps on every click and fits on one line.
  • Every panel opens with its name as a real heading and two quiet round buttons, ? (that panel's walkthrough) and ×, instead of a "? How this panel works" text link.
  • The Timeline is a labelled waterfall: method and path beside each bar, the duration after it, every row in the session (it stopped after nine), and rows open from the keyboard.
  • Fewer things on screen at once: Compose's five import/export buttons sit in one closed "Import & export"; WebSocket shows captured activity first with "Inject a message" folded below; Settings' Done stays pinned at the bottom; History's Compare buttons appear once a session is ticked; the duplicate fox logo left the recording bar.
  • Past sessions read "Total 42 · Error 1 · Slow 2" instead of "42 reqs · 1 err · 0 dup · 2 slow · 0 js-err"; per-endpoint counts read "×2" instead of "1 reqs".

That string used to sit in the pill and, in Firefox's ~300px sidebar, squeezed the path into a one-letter-wide column. A cancelled beacon (ERR_ABORTED, not counted as an error) keeps its grey pill.

Accessibility

API

  • Paste a curl copied with Chrome/Edge DevTools' Copy as cURL (cmd) on Windows: its ^-escaped quotes used to come out as a body of ^^{^^a^^:1^}^. curl.exe … (how PowerShell users type it) is accepted too.
  • Copy as cURL leaves out Content-Length (wrong as soon as a body was cut off at the size limit, and the server then waits for bytes that never come) and HTTP/2 pseudo-headers, and turns Accept-Encoding into --compressed so the reply prints as text.
  • The session summary sent with every captured request is one pass over the log instead of four filtered copies of it.

API: see more, trust what you see

  • GraphQL and JSON-RPC failures are failures. A 200 OK whose body has a GraphQL errors list (on a request that is GraphQL) or a JSON-RPC 2.0 error is flagged as an error, badged GRAPHQL ERROR / RPC ERROR with the server's message on the card, counted, and notified. GraphQL APIs answer 200 to almost everything, so their failed calls used to be invisible. The CI tool fails on them too ("bodyErrors": false turns that off).
  • Every request's timing, as DevTools' Timing tab shows it: queued, DNS, connect (with TLS), waiting for the server, download, the HTTP version, and bytes on the wire against bytes decoded — under Details on any card, the biggest phase in bold. A cross-origin API without Timing-Allow-Origin shows only what the browser exposes, never made-up numbers.
  • Called from: the page functions that made each call (fetchProducts (catalog.js:142) ← loadNextPage …) — for a duplicate call, which code fired it. Both also go into "Copy bug report" and the HAR export.
  • HAR export uses the real timing split and HTTP version, real transferred/decoded sizes, and dates each entry from when the request started (it used the finish time, shifting every bar in a HAR viewer).
  • Bodies are shown exactly as sent. Pretty-printing JSON no longer changes values: a 64-bit id 1234567890123456789 used to display as …456800, a repeated key lost a copy, 1.50 became 1.5.
  • A binary request body (an upload, protobuf, gzip) is named for what it is instead of a wall of replacement characters, a file in a multipart form is marked by its name, and Replay won't send that stand-in as the body — Edit & Replay lets you supply one.

API: mocking and testing

  • Mock this response and Block this request on any card's More menu: one click turns a captured call into a mock that replays its status, headers and body, or into a network error — scoped to that call's method and URL.
  • Mock and fault rules can name a method (a GET mock no longer catches POST), a mock replays its own headers (fetch and XHR's getResponseHeader both see them — jQuery picks its parser from Content-Type), and a mocked 204/304 no longer throws inside the page's fetch().
  • New rule mode Network error: the call fails the way a dropped connection does — fetch() rejects, XHR fires error with status 0 — for testing offline and retry handling. Sequences take an offline step too.
  • Dynamic variables under Postman's own names, new on every send: {{$guid}}, {{$timestamp}}, {{$isoTimestamp}}, {{$randomInt}}, {{$randomEmail}}, {{$randomUserName}}, … — in Compose, saved requests, suites and the CI tool, with or without an environment.
  • Compose sends OPTIONS (a CORS preflight, by hand).
  • Compose has a Params tab: the URL's query as one name=value per line, kept in step with the URL both ways — {{variables}} are never encoded, a + reads as the space a server sees, the #fragment stays.
  • Compose's Body takes a Form (URL-encoded) or a Multipart form with files, as well as raw text. The page builds a real FormData, so the browser writes the multipart boundary; a saved multipart request keeps its text fields (a browser won't let an extension keep files, and says so).
  • Header rules can change what the page receives: urlContains|responseheader|Name|Value and urlContains|removeresponseheader|Name — e.g. add Access-Control-Allow-Origin while a backend's CORS isn't ready.
  • Open a connection in the WebSocket panel: a WebSocket client of its own — connect to any ws:///wss:// server, send (Ctrl+Enter), see every frame each way, with {{variables}} in the URL and messages.
  • Generated k6, Playwright and Cypress scripts escape a U+2028/U+2029 in a captured body or header — k6's JavaScript engine reads a raw one as a line break inside a string, a syntax error.

API: in and out

  • Copy as code… on any card: cURL (bash and Windows cmd), PowerShell, fetch, Node.js, Python requests, HTTPie, Go and Java, each following its own quoting rules and client limits (PowerShell 5.1's -ContentType, headers fetch() refuses). The Windows cURL doubles a backslash only where the C runtime would eat it — DevTools' own "Copy as cURL (cmd)" doubles every one, and curl.exe then sends them doubled (checked in a real cmd.exe), breaking a JSON body with an escape in it.
  • Import a collection… reads Postman, Insomnia (v4 JSON and v5 YAML), Bruno, Hoppscotch and Thunder Client exports and HAR files: folders as name prefixes, disabled headers and params left out, auth as headers, and each tool's variable syntax ({{ _.x }}, <<x>>) rewritten to {{x}} for your environments.
  • OpenAPI / Swagger import handles Swagger 2.0, $ref parameters and request bodies, allOf/oneOf, +json and form media types, server {variables}, sample values for formats (date-time, email, uuid), and turns security schemes into Authorization: Bearer {{scheme}}-style headers. Before, an allOf body or a $ref parameter came out empty.

Store listing

How to mock an API response without a backend

RequestFox is a browser extension that can mock an API response without a backend: open a recorded call and press Mock on its card, change the status or the body if you want, then press Mock it and reload the page. From then on the page gets your response instead of the server's, for the calls it makes with fetch and XMLHttpRequest, and the call is labelled Mocked. Chrome DevTools local overrides and Mock Service Worker are two other ways, compared below.

For RequestFox 2.5.0, checked 19 November 2026.

Steps

  1. Record the real call once

    Press Start Recording and do what makes the call, so RequestFox has its real status, headers and body to start from.

  2. Press Mock on the card

    Open the call's card and press Mock, next to Replay. The dialog holds the response the server sent: its status and its body. It also works for a call that got no response at all (the backend is down). Then it starts with 200 and {}.

  3. Change the response, then Mock it

    Change the status or the body to what you want to test: an empty list, an error, a missing field. Press Mock it. More options… opens the full rule (method, how the address is matched, content type, a GraphQL operation).

  4. Make the call again

    Reload the page, or do the action in the page again. The page receives your response, and the card shows Mocked so nobody files it as a bug. Replay and Compose always call the real server, so use the page itself to see the mock.

If the mock does not answer

Open the call again. When a mock didn't answer it, the card says why, in these words:

  • The card says Not mocked: its mock is switched off. Press Mock off on the card, then Turn on.
  • Not mocked: the page made this call before RequestFox was ready. Reload the page again. The page's very first calls can come before RequestFox is ready, and a second reload catches them.
  • Not mocked: the page itself did not make this call (a worker, a beacon or a frame RequestFox can't reach), so a mock can't answer it. Mock the call the page makes instead, if there is one.
  • You pressed Replay or sent it from Compose: Not mocked: Replay and Compose always call the real server. Use the page itself.
  • Nothing is recording and the mock isn't kept on: the card says Mock paused. Press Start Recording, or keep it on (below).
  • The page still shows old data: reload it. A mock answers the next call, not one the page already made.

Keep a mock on without recording

On the card press Mocked, then Keep it on without recording…, and name the site (for example localhost). The mock then answers on that site in every tab, with nothing recording, until you turn it off. A chip under the top bar says Mock set on: localhost, with the set's name.

Mock a call that was never recorded

Settings → Mocks & rules → Mock or break an endpoint → Add rule…, with the mode Mock: type the part of the address to match, the status and the body.

Break a call instead

Settings → Mocks & rules → Mock or break an endpoint → Add rule…. Give the part of the address to match, a method, and a mode:

  • Fail: answer with an error status you pick.
  • Network error: fail the way a dropped connection does.
  • Slow or Throttle: add a delay, or slow the response by its size.
  • Mock: return the response you write.
  • Breakpoint (request) or Breakpoint (response): pause the call so you can edit it before it goes on.
  • Cycle: answer differently on each call.

Calls you broke on purpose are labelled Simulated.

When you are done

The call's card says Mocked: press it to edit the response, keep it on without recording, turn it off or delete the mock. After Stop it says Mock paused, and the mock waits for the next recording. While any rule is on, the recording bar says "Mocks on (n)": press it to see every rule. A mock answers only while RequestFox records the tab, unless you keep it on without recording, and only the calls the page makes with fetch or XMLHttpRequest (not a worker's calls, images or scripts).

DevTools local overrides, Mock Service Worker or an extension?

Here are three ways to change what an API call returns in the browser, side by side. Local overrides are part of Chrome DevTools, so there's nothing to install. Mock Service Worker is a library you add to your own app. An extension such as RequestFox works on any site and starts from a call it recorded.

 DevTools local overridesMock Service WorkerRequestFox mock rule
Where it livesIn Chrome DevTools; changes are saved as files in a folder you choose [1]A library in your own project's code [2]In the extension, beside your page
Needs the app's codeNo; it can mock resources you have no access to [1]YesNo
What it changesA response's content and headers, including XHR and fetch responses [1]The requests your app makes: it intercepts, observes and changes them [2]The status, headers and body of a call it recorded; or it makes a call fail, slow down or pause
Worth knowingIt turns the browser cache off while overrides are on [1]In the browser it uses the Service Worker API; in Node.js it works differently [2]It changes fetch and XMLHttpRequest calls the page makes, and labels them Mocked or Simulated

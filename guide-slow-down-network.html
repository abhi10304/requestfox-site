How to slow down or cut off the network for one call or a whole tab

Open Mock or break an endpoint in RequestFox, a browser extension for Chrome and Firefox, press Add rule, type part of the call's URL and pick a mode: Slow holds the call back for the milliseconds you set, Throttle makes a bigger response take longer, and Network error fails the call as if the server can't be reached. The rule works while RequestFox records. In Chrome, Slow down the whole tab makes one tab load as if on Slow 3G, Fast 3G, 4G or no network at all: the page, its scripts, images and API calls.

For RequestFox 2.5.0, checked 17 November 2026.

How do I make one API call slow or fail?

  1. Open Mock or break an endpoint

    In RequestFox, open Settings → Mocks & rules → Mock or break an endpoint, and press Add rule….

  2. Say which call it is for

    In URL contains, type part of the call's address, such as /api/search. Leave Method on Any method, or pick one.

  3. Pick the mode

    In Mode, a new rule starts on Mock. Pick Slow and type the Delay ms, such as 4000; or pick Network error to fail the call with no response at all. Throttle is under More ways: type a speed in KB/s, and the bigger the response, the longer the page waits for it.

  4. Save it and record

    Press Save rule, then Start Recording and use the page. Each call that matches is slowed down or cut off; the others go through as usual.

  5. Watch the page cope

    Look for the spinner, the timeout and the error message the page shows. A call cut off by your rule says Simulated on its card, so nobody files it as a real bug.

To make a call fail only some of the time, pick Cycle under More ways and write one step per line, such as pass, pass, offline: the steps take turns, call by call, and start again after the last line.

How do I slow down a whole tab?

In Chrome, open Settings → Mocks & rules → Slow down the whole tab. Pick a Speed: Slow 3G (2 s delay, 400 kbit/s), Fast 3G (0.56 s delay, 1.4 Mbit/s), 4G (0.17 s delay, 8.1 Mbit/s), Offline, or Custom with your own delay and speeds. Then press Turn on for this tab.

RequestFox uses Chrome's debugger connection to that tab, so the first time Chrome asks you to allow it, and while it is on Chrome shows its own "started debugging this browser" bar. Only the speed changes; nothing is read. One tab is slowed at a time, and it goes back to normal speed when you press Turn off, stop recording, close the tab, close the RequestFox panel or close Chrome's bar.

Firefox can't slow down a whole tab: it has no such API for extensions. There, a Slow or Throttle rule slows the calls you pick.

Can a slow call stay slow with nothing recording?

Yes, for Slow and Network error. Save the rule with nothing recording, and the line under it offers Keep it on without recording…: press it, and name the site (for example localhost) in the mock set it opens with your rule. The rule then works on that site in every tab, with nothing recording, until you turn the set off. Throttle works only while you record.

What if the call is not slowed down?

  • Nothing is recording. The rules in this list say Works while you record. Press Start Recording, or keep the rule on in a mock set.
  • It is a page load, an image or a script. A rule changes the fetch and XMLHttpRequest calls the page makes. In Chrome, slow down the whole tab instead.
  • The address does not match. Open the call's card and copy part of its URL into URL contains.
  • The card's time looks normal. Slow holds the call back before it is sent, and Throttle holds the response back on its way to the page, so the card times only the network part. The page itself still waited.
  • Chrome will not slow down the tab. Chrome doesn't let extensions slow down its own pages or the Web Store, and only one tool can debug a tab at a time: close DevTools on that tab, then press Turn on for this tab again.

Can DevTools do this?

Yes, for the tab it inspects. Chrome's Network panel has a throttling menu with presets such as fast 4G, slow 4G and 3G, an Offline choice and your own profiles [1]. Firefox's network monitor has presets from GPRS to Wi-Fi, and Offline [2]. DevTools slows down everything in that tab; a RequestFox rule slows down or cuts off only the calls you pick, and marks them in the log.

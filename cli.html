The RequestFox command line

requestfox-ci.mjs is RequestFox's command line: one file with no dependencies, for Node 18 or newer, that you download from the panel. Run node requestfox-ci.mjs <command> in a terminal or a CI job. It exits 0 when everything passed, 1 when a check or finding failed, and 2 when the command could not run.

For RequestFox 2.5.0, checked 19 November 2026.

Get the file

The command line ships inside the extension, so there is nothing to install and its version is the extension's. Two buttons save it:

  • From a test suite: on the suite's card choose ··· → Export as CI config, then press Download the CLI in the dialog. You get requestfox.config.json and requestfox-ci.mjs. The CI guide goes through it step by step.
  • From Settings → Sign-in, cookies & connections → MCP control: press Download the CLI.

Put the file next to your config and check that it runs:

node requestfox-ci.mjs --version

It prints requestfox-ci 2.5.0.

Commands

Twelve commands. Each line shows the flags it needs; node requestfox-ci.mjs <command> --help prints all of its flags.

CommandWhat it does
assert --config <file>Sends every request in the config for real and checks every rule. A step with no check fails when the response is 4xx or 5xx.
diff --config <file>Compares each response's shape with a saved baseline. --save-baseline writes the baseline first.
run <folder>Runs a workspace folder (the one RequestFox keeps for git) or a workspace.json, suite by suite. --suite and --env pick one suite and one environment.
loadtest --config <file>Sends the config's requests from many virtual users (--vus 10 --duration 30s), at a fixed rate (--rate 50), or in steps until the API slows down (--find-breakpoint). Load-test only a system you own or have permission to test.
merge-results --file <file> --file <file>Combines loadtest --json files written on several machines into one result.
conform --spec <file> --session <file>Checks a recorded session or HAR against an OpenAPI spec, or against a GraphQL schema with --graphql-schema. Exit 1 on a mismatch or a call that is not in the spec. How.
probe --spec <file> --base <address>Makes tests from an OpenAPI spec and sends them: each case breaks one rule, and your API must refuse it with a 4xx. Careful by default: this computer only, GET, HEAD, OPTIONS and QUERY only, 5 requests a second and at most 200 cases, unless you allow more.
mock --spec <file>A local mock server on 127.0.0.1, from a spec, from a recorded session (--session) or from a workspace's saved examples (--workspace). --dynamic varies the responses; --seed 42 repeats them.
docs --workspace <folder> --out docs.htmlYour saved collections as one HTML page of API docs, with no request sent. Passwords, tokens and keys become {{variables}}.
device-login --device-url <address> --token-url <address> --client-id <id>OAuth 2.0 device code sign-in: shows the page and the code, waits for you to approve, and prints the access token.
explain <code>What a finding code such as RF-SLOW means, why it is flagged and what to do. With no code it lists them all.
mcp --http <port> --controlRequestFox's MCP server, for an AI tool on this computer, over stdio or, with --http, over HTTP on 127.0.0.1. --control lets the panel pair with it (Settings → MCP control). RequestFox runs no AI model.

Exit codes

CodeMeans
0Everything passed.
1A check or a finding failed. A load test fails only on a threshold; with none it exits 0.
2The command could not run, for example: an unknown flag, a config that does not load, a missing baseline, scripts without --allow-scripts, or an environment variable that is not allowed.

Environment variables and secrets

A config reads a secret as {{env:NAME}}, so the value stays out of the file. The command must name each variable it may read: add --allow-env NAME (names separated by commas, or the flag again; * allows all), or set REQUESTFOX_ALLOW_ENV=NAME,NAME. Without it the run stops before any request, with exit code 2 and one sentence that names the variable.

node requestfox-ci.mjs assert --config requestfox.config.json --allow-env API_TOKEN

In the log and the JUnit file, values of fields and headers that look like secrets are shown as "hidden".

The config file

assert, diff and loadtest read requestfox.config.json (--config <file>). A suite card's ··· → Export as CI config writes one; you can also write it by hand. A small one:

{
  "baseUrl": "http://localhost:3000",
  "requests": [
    { "name": "List users", "method": "GET", "path": "/users" }
  ],
  "assertions": [
    { "pattern": "/users", "type": "status", "op": "=", "value": 200 },
    { "pattern": "/users", "type": "latency", "op": "<", "value": 800 }
  ]
}

Top level

FieldWhat it is
baseUrlRequired. A full address, like http://localhost:3000. {{env:NAME}} and {{name}} from variables work in it.
requestsRequired for assert and diff: the steps, in order (fields below).
variables{ "name": "value" }, used as {{name}} in any step.
dataRows for a data-driven run, [{ "sku": "A-1" }, ...]: the steps run once per row, each row's fields as {{sku}}.
dataFileThe same rows from a CSV or JSON file beside the config.
assertionsThe checks (fields below). A step that no check applies to fails on a 4xx or 5xx.
timeoutMsTime limit for each request, in ms.
scriptTimeoutMsTime limit for each script, in ms.
delayMsWait between steps, 0 to 60000 ms (--delay-ms).
bailtrue: stop at the first failure (--bail).
iterationsRepeat the whole run 1 to 100 times (--iterations).
retryCountSend a step that did not pass again, 0 to 10 times.
httpErrorsfalse: a 4xx or 5xx fails a step only through a check.
bodyErrorsfalse: an error inside a 2xx response (GraphQL, JSON-RPC) does not fail the step.
securityfalse: no security scan of the responses. "securityHeaders": false leaves out the header checks; "securityHeuristics": true adds the guesses.
failOnSecuritytrue: a security finding fails the run.
baselineFileWhere diff keeps the shapes (by default .requestfox-baseline.json beside the config).
nameThe run's name in the reports.
loadTestloadtest's own options (below).

Each request

FieldWhat it is
nameThe step's name in the log and the reports.
method, path"GET" and "/users/42", added to baseUrl (a full address works too).
headers{ "Name": "value" }
bodyThe body: text, or a JSON value.
authThe sign-in an exported suite carries, like { "type": "bearer", ... }.
extractValues to save from the response, used as {{name}} by later steps.
pathVariablesValues for the :name parts of the path.
preRequestScript, postResponseScriptScripts; they need --allow-scripts.
timeoutMsThis request's own time limit, in ms.

Each check in "assertions"

FieldWhat it is
patternPart of the request addresses it applies to, like "/users".
typestatus, latency, field, header, xpath, schema or same.
pathThe field (like data.items[0].id), the header name or the XPath.
op= != < <= > >= exists notexists contains notcontains matches
valueWhat to compare with.
enabledfalse: switched off (counted once in the summary).

"loadTest"

FieldWhat it is
vus, durationSec, rampUpSec, iterationsVirtual users, how long, the ramp-up, and runs per user.
stages[{ "duration": "30s", "targetVus": 10 }, ...] in place of vus and durationSec.
arrivalRate{ "ratePerSec": 50, "maxVus": 100 }: a fixed rate (the open model).
thresholdsp95, p99, maxLatencyMs, errorRatePct, droppedIterationsPct: the run fails when one is passed. With none, loadtest always exits 0.
requests, data, dataFileThe load test's own steps and rows (otherwise the top-level ones).
healthCheck{ "path": "/health", "intervalSec": 5 }: checked while the test runs.

Flags several commands share

FlagWhat it does
--var name=valueSets {{name}} for this run; give the flag again for more. Commands: assert, diff, loadtest and run.
--allow-env NAMELets the config read these environment variables (above). Commands: assert, diff, loadtest, run and mcp.
--allow-scriptsRuns the pre-request and post-response scripts a config or folder holds; without it, one with scripts is refused. A script runs in a worker thread with its Node powers removed, but that is not a security sandbox: use it only for files you trust. Commands: assert, diff, run and mcp.
--reporter junitWrites a JUnit XML report to the file --out names, for your CI's test view. assert and run also write json and html: --reporter junit,json,html. Commands: assert, diff, run and conform.
--baseline <file>, --update-baselineFails only on findings that are not in the file; --update-baseline writes this run's findings to it instead. Commit it: it holds codes and places only, no values or secrets. Commands: assert, run, conform and probe.
--http2Sends every request over HTTP/2: h2 on an https address, h2c on an http one. A server that does not speak it is an error, never a quiet fall-back to HTTP/1.1. Commands: assert, diff, loadtest, run and probe.
--cert <file>, --key <file>A client certificate (mTLS). Commands: assert, diff, loadtest, run and probe.
--ca <file>Trusts a private certificate authority as well; give it again for more. Commands: assert, diff, loadtest, run and probe.
--proxy <address>Goes through an http proxy. Commands: assert, diff, loadtest, run and probe.
--insecureSkips certificate checks, for a staging server only. Commands: assert, diff, loadtest, run and probe.
--location-trustedOn a redirect to another site, sends the credential headers (Authorization, Cookie, API keys) on too. Without it they stay behind and one line says so. Commands: assert, diff, loadtest and run.
--cookie-jar <file>Keeps cookies between requests, like a browser: read from the file, updated by each response and written back when the run ends. Values are never printed; keep the file out of git. Commands: assert and run.
--data <file>Runs the steps once per row of a CSV file (its first line names the columns) or a JSON list of objects, in place of the config's own rows. A missing, empty or broken file stops the run before any request. Commands: assert and run.

Help in the terminal

The file carries the same help, so you can read it offline:

  • node requestfox-ci.mjs --help: every command on one screen, and the exit codes.
  • node requestfox-ci.mjs assert --help: one command and all of its flags.
  • node requestfox-ci.mjs help config: the config file's fields, as in the tables above.
  • node requestfox-ci.mjs explain RF-SLOW: what a finding code on a failure line means.
  • node requestfox-ci.mjs mcp --help: the MCP server's flags.

हर समस्या, सीधे शब्दों में

कॉल पूरी होते ही परखी जाती है। पैनल उसके बारे में क्या कहता है, यह पढ़ने के लिए एक फ़्लैग चुनें।

फ़्लैग

POST /api/orders 500 412 ms

यह फ़्लैग क्यों है?

जवाब देते समय सर्वर फ़ेल हो गया (5xx स्टेटस)।

क्या करें: इस समय के सर्वर लॉग देखें; “फिर से भेजें” वही request दोबारा भेजता है ताकि पता चले कि यह दोहराता है या नहीं।

GET /api/search?q=boots 200 3.1 s

यह फ़्लैग क्यों है?

Response में आपकी धीमेपन की सीमा से ज़्यादा समय लगा।

क्या करें: विवरण में टाइमिंग बताती है कि समय कहाँ गया; सीमा सेटिंग्स में है।

POST /graphql 200 96 ms

यह फ़्लैग क्यों है?

Response कहता है कि कॉल फ़ेल हुई, जबकि उसका HTTP स्टेटस OK है।

क्या करें: Response में दिया गया एरर पढ़ें: सिर्फ़ स्टेटस देखने से यह फ़ेल होना छिप जाता है।

GET /api/me 401 54 ms

यह फ़्लैग क्यों है?

कॉल मना कर दी गई और उसका भेजा token पहले ही खत्म हो चुका था।

क्या करें: फिर से साइन इन करें या token रीफ़्रेश करें, फिर कॉल दोबारा भेजें।

GET /api/cart 200 120 ms

यह फ़्लैग क्यों है?

Response का ढाँचा (उसके फ़ील्ड और उनके टाइप) वैसा नहीं है जैसा यह कॉल पहले लौटाती थी।

क्या करें: क्या बदला, देखने के लिए कार्ड पर ढाँचे का डिफ़ खोलें।

GET /api/stock/42 503 230 ms

यह फ़्लैग क्यों है?

यह कॉल कुछ रिकॉर्ड किए गए सेशन में फ़ेल हुई और कुछ में पास।

क्या करें: हिस्ट्री में एक फ़ेल और एक पास response की तुलना करें।

RequestFox के लगाए सभी फ़्लैग

फ़्लैग से हल तक

01 फिर से भेजें

फिर से भेजें, या पहले बदलें

रिकॉर्ड की गई किसी भी कॉल को जैसी थी वैसी फिर से भेजें, या उसे “बनाएँ” में बदलें। एनवायरनमेंट, {{variables}}, डिवाइस कोड वाला OAuth 2.0, OAuth 1.0a, JWT Bearer और AWS Signature v4 पहले से मौजूद हैं, और कई request एक साथ खुली रह सकती हैं।

Request और कलेक्शन पर सेव किए गए उदाहरण और नोट रखें। हर साइट के लिए आप जो cookie जार चालू करते हैं, वह साइन-इन को आपकी अगली भेजी गई request तक ले जाता है, और WebSocket क्लाइंट में एक Socket.IO मोड है।

किसी request को फिर से कैसे भेजें और बदलें

02 Mock

Mock बनाएँ, तोड़ें, धीमा करें

एक कॉल खोलें और “Mock” दबाएँ: उसका असली स्टेटस और body बदलने के लिए तैयार हैं। “Mock बनाएँ” दबाएँ, पेज रीलोड करें, और पेज को आपका response मिलता है। कोई नियम बैकएंड को छुए बिना किसी कॉल को फ़ेल भी कर सकता है, धीमा कर सकता है या रोक सकता है। नियम सेट और mock सेट तब तक चालू रहते हैं जब तक आप चाहें।

Chrome में आप पूरे टैब को धीमा भी कर सकते हैं, या किसी request या response को स्क्रिप्ट से दोबारा लिख सकते हैं। जिन कॉल को आपने बदला, उन पर Mock या सिम्युलेटेड लेबल रहता है, ताकि कोई उन्हें असली बग न समझे।

API response का mock कैसे बनाएँ

03 टेस्ट

जाँचें, फिर वही जाँच CI में चलाएँ

किसी एंडपॉइंट में जाँच जोड़ें: स्टेटस, समय, फ़ील्ड, header या कोई JSON Schema, और सेव की गई request को जोड़कर सुइट बनाएँ। डाउनलोड होने वाला कमांड-लाइन टूल उन्हें आपकी पाइपलाइन में चलाता है और कोई जाँच फ़ेल होने पर बिल्ड फ़ेल कर देता है। आपको कैशिंग और कम्प्रेशन पर सलाह भी मिलती है, और एक जाँच कि कोई response पिछली बार जैसा ही बना रहे।

कलेक्शन Postman, Insomnia, Bruno, Hoppscotch और Thunder Client, OpenAPI 3, Swagger 2, WSDL, HAR और cURL से आते हैं। वे वापस Postman कलेक्शन, Bruno, Insomnia और Hoppscotch के लिए कलेक्शन, OpenAPI 3.0, एक API डॉक्स पेज, 15 भाषाओं में कोड, या Playwright, Cypress, k6, JMeter, Gatling और Locust स्क्रिप्ट के रूप में निकलते हैं।

अपनी API जाँच CI में कैसे चलाएँ

04 AI टूल

अपने AI टूल टेस्ट करें, अंदर कोई AI नहीं

RequestFox कोई AI मॉडल नहीं चलाता। यह आपके बनाए AI टूल टेस्ट करता है: “बनाएँ” एक MCP सर्वर से जुड़ता है और उसके टूल कॉल करता है, और किसी लैंग्वेज-मॉडल API को की गई कॉल मॉडल, response में दी गई token गिनती, रुकने का कारण और समय दिखाती है।

MCP कंट्रोल चालू होने पर (यह डिफ़ॉल्ट रूप से बंद है), आपके अपने कंप्यूटर पर चलने वाला एक AI एजेंट RequestFox के ज़रिए रिकॉर्ड कर सकता है, फिर से भेज सकता है और mock बना सकता है। हर बार भेजने और फिर से भेजने से पहले आपके क्लिक का इंतज़ार होता है।

क्या यह MCP कार्रवाई होने दें?

एक लोकल MCP क्लाइंट यह माँग रहा है: भेजें POST shop.example.com/api/orders। जब तक आप अनुमति न दें, कुछ नहीं होगा।

रद्द करेंअनुमति दें

Alt Shift S दबाएँ, फिर अपना ऐप इस्तेमाल करें।

हर fetch, XMLHttpRequest, WebSocket फ़्रेम और सर्वर-सेंट इवेंट शुरू होते ही दिखता है, टैब, फ़्रेम और पॉप-अप के पार, यहाँ तक कि वे कॉल भी जिनका response कोई सर्विस वर्कर देता है।

हर कॉल उस क्लिक या फ़ॉर्म सबमिट से जुड़ी होती है जिससे वह हुई, और हर सेशन अगले से तुलना के लिए “हिस्ट्री” में रखा जाता है।

Mac पर यही शॉर्टकट Option Shift S है। या साइड पैनल खोलें और “रिकॉर्डिंग शुरू करें” दबाएँ। API कॉल चरण-दर-चरण कैसे रिकॉर्ड करें

QA टेस्टर, फ़्रंटएंड डेवलपर और API डेवलपर के लिए लिखा गया। सभी गाइड, जिनमें कॉल को OpenAPI spec से जाँचना भी शामिल है।

सवाल

क्या RequestFox मुफ़्त है?

हाँ। RequestFox मुफ़्त है, और हमारा वादा यहाँ लिखा है: जो कुछ आप आज मुफ़्त में इस्तेमाल कर सकते हैं, वह बाद में कभी पेड नहीं होगा। इसमें कोई विज्ञापन, कोई अकाउंट और कोई पेड प्लान नहीं है।

क्या RequestFox मेरा डेटा कहीं भेजता है?

नहीं। RequestFox जो कुछ रिकॉर्ड करता है, वह आपके डिवाइस पर आपके ब्राउज़र के स्टोरेज में रहता है। कोई RequestFox सर्वर, कोई एनालिटिक्स और कोई अकाउंट नहीं है। RequestFox जो कुछ रखता है, लॉग करता है या एक्सपोर्ट करता है, उस सब में Authorization header, cookie और सीक्रेट जैसे दिखने वाले फ़ील्ड डिफ़ॉल्ट रूप से छिपाए जाते हैं (“बनाएँ” आपकी अपनी request का response वैसा ही दिखाता है जैसा वह आया; उसकी हाल की सूची आपकी पिछली 100 भेजी गई request को, छिपाकर, इस डिवाइस पर तब तक रखती है जब तक आप “साफ़ करें” न दबाएँ), और साइट एक्सेस सिर्फ़ तब माँगा जाता है जब आप “रिकॉर्डिंग शुरू करें” दबाते हैं, या, संबंधित साइटों के लिए, जब आप “बनाएँ” से भेजते हैं या कुछ भी रिकॉर्ड न होते हुए कोई टेस्ट सुइट चलाते हैं।

क्या RequestFox AI इस्तेमाल करता है?

नहीं। RequestFox कोई AI मॉडल नहीं चलाता। यह आपके बनाए AI टूल टेस्ट कर सकता है: MCP सर्वर, और वे कॉल जो कोई पेज किसी लैंग्वेज-मॉडल API को करता है। MCP कंट्रोल चालू होने पर, जो डिफ़ॉल्ट रूप से बंद है, आपके अपने कंप्यूटर पर चलने वाला एक AI एजेंट इसे चला सकता है, और हर बार भेजने से पहले आपके क्लिक का इंतज़ार होता है।

RequestFox एक मुफ़्त ब्राउज़र एक्सटेंशन है जो एनवायरनमेंट, {{variables}}, OAuth 2.0 समेत ऑथ हेल्पर और सेव किए गए कलेक्शन के साथ request बनाता और भेजता है, Postman, Insomnia, Bruno, Hoppscotch और Thunder Client कलेक्शन इम्पोर्ट करता है, और Postman कलेक्शन तथा Bruno, Insomnia और Hoppscotch के लिए कलेक्शन एक्सपोर्ट करता है। किसी अलग क्लाइंट के उलट, यह वे कॉल भी रिकॉर्ड करता है जो आपका वेब ऐप असल में करता है। इसमें कोई क्लाउड वर्कस्पेस या टीम सिंक नहीं है।

RequestFox, DevTools के Network पैनल से कैसे अलग है?

DevTools हर request दिखाता है और परखना आप पर छोड़ता है। RequestFox फ़ेल, धीमी, दोहराई गई और दोबारा कोशिश की गई कॉल को होते ही फ़्लैग करता है, हर कॉल को उस क्लिक से जोड़ता है जिससे वह हुई, हर एंडपॉइंट के आपके नियम जाँचता है, और हर सेशन रखता है ताकि आप आज के रन की तुलना कल के रन से कर सकें। किसी पेज के लोड की गई हर चीज़ पर कच्ची, लाइव नज़र के लिए DevTools बेहतर है।

How to send an API bug report with the evidence

Record the bug with RequestFox, a browser extension for Chrome, Edge and Firefox, open the call that failed and choose Copy bug report from its More menu. You get one text to paste into the ticket: the request and its status, the clicks that led to it, the console lines around it, the headers and bodies, and a cURL command that repeats it, with tokens and passwords hidden. For the whole session, Export an HTML report (screenshots included) or a HAR.

For RequestFox 2.5.0, checked 17 November 2026.

How do I report one failed call?

  1. Turn on screenshots, if you want one

    In Settings → Privacy & evidence, tick Take a screenshot when a call is flagged. A flagged call then keeps a picture of the page as it was.

  2. Record the bug

    Press Start Recording and do what goes wrong, step by step, as a user would.

  3. Find the call

    Press Failed above the list, or search for the address. The card says what is wrong with the call, such as its status or Token expired.

  4. Copy the bug report

    On the card, press More → Copy bug report, and paste it into the ticket or the chat.

  5. Check what it hid

    Read it before you send it. When it hid a token, a cookie or a password, it ends with "Secrets were hidden in this copy." The developer can still repeat the call with their own sign-in.

What does the bug report hold?

  • The method and address, the page it came from, the status and how long it took.
  • Its flags in capitals, such as ERROR, SLOW, TOKEN EXPIRED or GRAPHQL ERROR, and the error inside the body when there is one.
  • The line of code that made the call and the click that set it off, when RequestFox saw them.
  • "Steps before this call:", the steps that led up to it, and "Console around it:", the page's console errors and warnings from that moment when you record them.
  • The request and response headers and bodies; a body cut short says so.
  • A cURL command that sends the call again, with notes on what to fill in first.

The report is built the way Export with secrets hidden writes a file, whatever Hide passwords, tokens and card numbers in what is recorded is set to, so a token in the address or a password in a login body does not go into a ticket.

Can I open an issue straight from the call?

Yes, in GitHub or Linear. Under Settings → Issue tracker, fill in GitHub repo (owner/repo) or Linear workspace slug. A call's More menu then offers Open GitHub issue or Open Linear issue: it opens a new issue in your browser with the title (method, path and status, never the query) and the report filled in, for you to read and submit. Nothing is sent until you press it. A long report is shortened to fit the address, and says so.

How do I send the whole session?

Press Export at the bottom of the panel. HTML report is one file anyone can open in a browser, with each call, its flags and its screenshot; HAR opens in DevTools and other tools. With a filter on, the menu also offers to export only the calls shown. If the session still holds a token, a cookie or a password as it was sent, Export asks first: Export with secrets hidden, or Export as it is.

Exporting a HAR from Chrome's DevTools instead? Its "Export HAR (sanitized)" leaves out the Cookie, Set-Cookie and Authorization headers; the export with sensitive data needs a setting turned on first [1]. Tokens in an address or a body are in both.

RequestFox or a proxy tool: HTTP Toolkit, Proxyman and Charles

RequestFox is a browser extension: it sees the calls a web app makes in a Chrome, Edge or Firefox tab, with nothing else to set up. HTTP Toolkit, Proxyman and Charles are apps you install on your computer that sit between your apps and the internet: they see the traffic of whatever you send through them, phones and desktop apps included, once that app or device trusts their certificate for HTTPS. Pick a proxy tool when the traffic isn't in a browser tab. Pick RequestFox when it is, and you'd like the broken calls flagged for you, with no certificate, no proxy setting and no account.

Facts about HTTP Toolkit, Proxyman and Charles are from their own pages, checked 15 November 2026; sources below. Written by the RequestFox team, for RequestFox 2.5.0.

Where are the proxy tools stronger?

  • Traffic from outside the browser: phones, simulators, desktop apps, Docker containers and terminals [1][4][6].
  • HTTPS from any app or device that trusts their certificate, mobile apps included [2][4][9].
  • One place to change the traffic of every app at once: breakpoints in all three [3][4][7], Map Local in Proxyman and Charles [4][8], Rewrite and Map Remote in Charles [8].
  • Charles slows the whole connection, with the bandwidth and latency you choose [7].
  • HTTP Toolkit is open source, according to its own page [1].

Where is RequestFox different?

  • Nothing to set up but the extension: no certificate to trust, no proxy setting, and the rest of your computer's traffic is left alone.
  • It judges the calls. Failed, slow, duplicate and retried requests, N+1 bursts, GraphQL errors in a 200, expired tokens and changed shapes are flagged as they happen, each tied to the click that caused it.
  • It keeps every session, so you can compare today's run with yesterday's, and turns a recording into checks you can run in CI.
  • Mock and fault rules label the calls they change, so nobody files a mocked response as a bug.
  • No account for anything, and nothing is sent to us.

Where RequestFox falls short, so you're not surprised:

  • It sees what a browser tab sends, in Chrome, Edge and Firefox: not a phone, a desktop app or a terminal.
  • Slowing a whole tab works in Chrome only; Firefox offers each rule's Slow and Throttle modes instead.
  • Rewriting a request or response with a script runs in Chrome only.
  • It is free. Its code is MIT-licensed and ships readable inside the extension, so you can check it yourself; the source repository is not public.

Can I use both?

Yes. They do different jobs. Use a proxy tool for the phone build or the desktop app, and RequestFox for the web app in the browser, where it flags the broken calls and turns a flow into checks.

백엔드 없이 API 응답을 모의로 만드는 방법

RequestFox는 백엔드 없이 API 응답을 모의로 만들 수 있는 브라우저 확장 프로그램입니다. 기록된 호출을 열고 카드에서 '모의'를 누른 뒤, 원하면 상태나 본문을 바꾸고 '모의 응답 만들기'를 누른 다음 페이지를 새로고침하세요. 그 뒤로 페이지가 fetch와 XMLHttpRequest로 보내는 호출에는 서버의 응답 대신 내 응답이 돌아가고, 호출에는 '모의' 라벨이 붙습니다. Chrome DevTools의 로컬 재정의(local overrides)와 Mock Service Worker도 방법이며, 아래에서 비교합니다.

RequestFox 2.5.0 기준, 2026년 11월 19일에 확인.

단계

  1. 실제 호출을 한 번 기록하기

    기록 시작을 누르고 그 호출을 일으키는 동작을 하세요. 그러면 RequestFox가 실제 상태, 헤더, 본문을 출발점으로 갖게 됩니다.

  2. 카드에서 '모의' 누르기

    호출의 카드를 열고 다시 보내기 옆의 모의를 누르세요. 대화 상자에는 서버가 보낸 응답, 즉 상태와 본문이 들어 있습니다. 응답을 전혀 받지 못한 호출(백엔드가 다운됨)에도 쓸 수 있습니다. 이때는 200과 {}로 시작합니다.

  3. 응답을 바꾼 뒤 모의로 만들기

    상태나 본문을 테스트하려는 내용으로 바꾸세요. 빈 목록, 오류, 빠진 필드 같은 것입니다. 모의 응답 만들기를 누르세요. 추가 옵션…은 전체 규칙(메서드, 주소를 맞추는 방법, 콘텐츠 유형, GraphQL 작업)을 엽니다.

  4. 호출을 다시 일으키기

    페이지를 새로고침하거나 페이지에서 같은 동작을 다시 하세요. 페이지는 내 응답을 받고, 카드에는 모의가 표시되어 아무도 버그로 신고하지 않습니다. 다시 보내기와 작성은 항상 실제 서버를 호출하므로, 모의 응답은 페이지 자체에서 확인하세요.

모의 응답이 오지 않을 때

호출을 다시 여세요. 모의 응답이 그 호출에 답하지 않았다면 카드가 그 이유를 이런 말로 알려 줍니다.

  • 카드 표시: 모의 응답 안 됨: 모의 응답이 꺼져 있습니다. 카드에서 모의 꺼짐을 누르고 켜기를 누르세요.
  • 모의 응답 안 됨: RequestFox가 준비되기 전에 페이지가 이 호출을 했습니다. 페이지를 다시 새로고침하세요. 페이지의 맨 처음 호출은 RequestFox가 준비되기 전에 올 수 있습니다. 한 번 더 새로고침하면 모의 응답이 답합니다.
  • 모의 응답 안 됨: 이 호출은 페이지 자체가 한 것이 아닙니다(워커, 비콘 또는 RequestFox가 닿지 않는 프레임). 그래서 모의 응답이 답할 수 없습니다. 페이지가 직접 보내는 호출이 있다면 대신 그 호출을 모의로 만드세요.
  • '다시 보내기'를 눌렀거나 '작성'에서 보낸 경우: 모의 응답 안 됨: '다시 보내기'와 '작성'은 항상 실제 서버를 호출합니다. 페이지 자체를 사용하세요.
  • 아무것도 기록하지 않고 모의 응답도 켜 두지 않았다면 카드에 모의 일시 중지됨이 표시됩니다. 기록 시작을 누르거나, 켜 두세요(아래 참고).
  • 페이지에 아직 오래된 데이터가 보이면 새로고침하세요. 모의 응답은 다음 호출에 답하며, 페이지가 이미 보낸 호출에는 답하지 않습니다.

기록 없이도 모의 응답 켜 두기

카드에서 모의 설정됨을 누르고 기록 없이도 켜 두기…를 누른 뒤 사이트를 입력하세요(예: localhost). 그러면 끌 때까지, 아무것도 기록하지 않아도 그 사이트의 모든 탭에서 모의 응답이 답합니다. 상단 바 아래의 칩에 세트 이름과 함께 모의 세트 켜짐: localhost가 표시됩니다.

한 번도 기록하지 않은 호출을 모의로 만들기

설정 → 모의 및 규칙 → 엔드포인트 모의 또는 장애 만들기 → 규칙 추가…에서 모드를 '모의'로 고르고, 맞출 주소의 일부, 상태, 본문을 입력하세요.

대신 호출을 고장 내기

설정 → 모의 및 규칙 → 엔드포인트 모의 또는 장애 만들기 → 규칙 추가…. 맞출 주소의 일부, 메서드, 모드를 정하세요.

  • 실패: 고른 오류 상태로 답합니다.
  • 네트워크 오류: 연결이 끊긴 것처럼 실패합니다.
  • 느림 또는 스로틀링: 지연을 더하거나, 응답을 크기에 따라 느리게 합니다.
  • 모의: 작성한 응답을 돌려줍니다.
  • 중단점(요청) 또는 중단점(응답): 호출을 멈춰서, 계속 진행되기 전에 수정할 수 있게 합니다.
  • 순환: 호출마다 다르게 답합니다.

일부러 고장 낸 호출에는 '시뮬레이션' 라벨이 붙습니다.

끝났을 때

호출의 카드에는 '모의 설정됨'이 표시됩니다. 누르면 응답 수정, 기록 없이도 켜 두기, 끄기, 모의 삭제를 할 수 있습니다. '중지' 뒤에는 '모의 일시 중지됨'이 표시되고, 모의 응답은 다음 기록을 기다립니다. 규칙이 하나라도 켜져 있는 동안 기록 바에 '모의 응답 켜짐 (n)'이 표시되며, 누르면 모든 규칙을 볼 수 있습니다. 모의 응답은 RequestFox가 그 탭을 기록하는 동안에만(기록 없이도 켜 둔 경우는 예외) 답하고, 페이지가 fetch나 XMLHttpRequest로 보내는 호출에만 답합니다(워커의 호출, 이미지, 스크립트는 제외).

DevTools 로컬 재정의, Mock Service Worker, 아니면 확장 프로그램?

브라우저에서 API 호출이 돌려주는 내용을 바꾸는 세 가지 방법을 나란히 놓았습니다. 로컬 재정의는 Chrome DevTools의 일부라 설치할 것이 없습니다. Mock Service Worker는 내 앱에 추가하는 라이브러리입니다. RequestFox 같은 확장 프로그램은 어느 사이트에서나 동작하고, 기록한 호출에서 출발합니다.

어떤 API 호출이 실패했는지 확인하세요.

로그인 없이 오프라인에서도 작동합니다. RequestFox는 Chrome과 Firefox의 사이드 패널에서 동작하는 무료 API 테스터이자 네트워크 모니터입니다. 웹 앱이 보내는 모든 호출을 기록하고, 문제가 생긴 호출에는 그 순간 플래그를 붙이며, 다시 보내고 모의 응답을 만들고 테스트할 수 있게 해 줍니다.

Chrome에 추가, 무료 Firefox에 추가

계정이 필요 없습니다. 저희에게 아무것도 전송되지 않습니다. AI가 들어 있지 않습니다.

RequestFox의 자리

이 API 테스트 도구들은 저마다 알맞은 일이 있습니다. 웹 앱을 테스트하면서 API 문제가 생기는 순간 대신 찾아 주기를 원한다면 RequestFox를 고르세요.

어떤 일에 어떤 도구를

  • 웹 앱을 테스트하면서 문제를 대신 찾아 주기를 원할 때

    RequestFox. 클릭하는 동안 호출을 기록하고, 실패했거나 늦어졌거나 두 번 나갔거나 200 OK 안에서 고장 난 호출에 플래그를 붙이며, 모든 세션을 보관합니다.

  • 한 번의 페이지 로드가 하는 모든 일을 날것 그대로 보고 싶을 때

    DevTools의 Network 패널. 브라우저에 기본으로 들어 있습니다. 거르고 읽는 일은 직접 합니다. RequestFox와 DevTools 비교

  • 팀에서 API를 설계하고 문서화하고 공유할 때

    Postman 또는 Insomnia. RequestFox는 둘 다에서 가져오고 둘 다로 내보낼 수 있습니다. RequestFox와 Postman 비교 · RequestFox와 Insomnia 비교

  • 요청을 Git에서 코드 옆에 일반 파일로 보관하고 싶을 때

    Bruno. Chrome에서는 RequestFox도 연결한 폴더에 컬렉션을 파일로 보관할 수 있습니다. RequestFox와 Bruno 비교

  • 직접 호스팅할 수 있는 웹 기반 오픈 소스 클라이언트를 원할 때

    Hoppscotch. RequestFox에는 호스팅할 것이 없습니다. 서버가 없기 때문입니다. RequestFox와 Hoppscotch 비교

RequestFox가 부족한 점

  • 브라우저 탭이 보내는 것만 봅니다. 모바일 앱과 데스크톱 앱에는 HTTP Toolkit, Proxyman, Charles 같은 프록시 도구가 필요합니다.
  • 팀 작업 공간이나 클라우드 동기화는 일부러 없습니다. 작업은 파일로 공유하세요: 컬렉션, 세션, HAR, 보고서.
  • 스크립트는 Chrome에서만 실행됩니다. Firefox는 확장 프로그램이 실행 중에 입력된 코드를 실행하도록 허용하지 않습니다.
  • 네이티브 gRPC나 MQTT 클라이언트는 없습니다(gRPC-Web과 Connect만 지원).

모든 비교, 출처와 함께

모든 문제를 쉬운 말로

호출은 끝나는 즉시 판정됩니다. 플래그를 골라 패널이 그에 대해 무엇이라고 하는지 읽어 보세요.

플래그

POST /api/orders 500 412 ms

왜 플래그가 붙었나요?

서버가 응답하는 중에 실패했습니다(5xx 상태).

할 일: 그 시점의 서버 로그를 확인하세요. '다시 보내기'로 같은 요청을 다시 보내 반복되는지 볼 수 있습니다.

GET /api/search?q=boots 200 3.1 s

왜 플래그가 붙었나요?

응답이 설정한 느림 한도보다 오래 걸렸습니다.

할 일: 세부 정보의 타이밍에서 시간이 어디에 쓰였는지 볼 수 있습니다. 한도는 설정에 있습니다.

POST /graphql 200 96 ms

왜 플래그가 붙었나요?

HTTP 상태는 OK이지만 응답에는 호출이 실패했다고 나와 있습니다.

할 일: 응답 안의 오류를 읽어 보세요. 상태만으로는 이 실패가 보이지 않습니다.

GET /api/me 401 54 ms

왜 플래그가 붙었나요?

호출이 거부되었고 보낸 토큰은 이미 만료되었습니다.

할 일: 다시 로그인하거나 토큰을 갱신한 뒤 호출을 다시 보내세요.

GET /api/cart 200 120 ms

왜 플래그가 붙었나요?

응답의 형태(필드와 타입)가 이 호출이 전에 돌려주던 것과 다릅니다.

할 일: 카드의 형태 비교를 열어 무엇이 바뀌었는지 확인하세요.

GET /api/stock/42 503 230 ms

왜 플래그가 붙었나요?

이 호출은 일부 기록 세션에서는 실패하고 다른 세션에서는 성공했습니다.

할 일: 내역에서 실패한 응답과 성공한 응답을 비교하세요.

RequestFox가 붙이는 모든 플래그

플래그에서 해결까지

01 다시 보내기

그대로 다시 보내거나, 먼저 수정하세요

기록된 호출을 그대로 다시 보내거나 '작성'에서 바꾸세요. 환경, {{변수}}, 기기 코드 방식의 OAuth 2.0, OAuth 1.0a, JWT Bearer, AWS Signature v4가 내장되어 있고, 여러 요청을 동시에 열어 둘 수 있습니다.

요청과 컬렉션에 저장된 예시와 메모를 남기세요. 사이트별로 켜는 쿠키 저장소가 로그인 상태를 다음 보내기에 이어 주고, WebSocket 클라이언트에는 Socket.IO 모드가 있습니다.

요청을 다시 보내고 수정하는 방법

02 모의

모의 응답, 장애, 지연

호출을 열고 '모의'를 누르세요. 실제 상태와 본문이 바로 고칠 수 있게 들어 있습니다. '모의 응답 만들기'를 누르고 페이지를 새로고침하면 페이지가 내 응답을 받습니다. 규칙으로 백엔드를 건드리지 않고 호출을 실패시키거나, 느리게 하거나, 잠시 멈출 수도 있습니다. 규칙 세트와 모의 세트는 원할 때 켜 둔 채로 둘 수 있습니다.

Chrome에서는 탭 전체를 느리게 하거나, 스크립트로 요청이나 응답을 다시 쓸 수도 있습니다. 바꾼 호출에는 모의 또는 시뮬레이션 라벨이 붙으므로 아무도 진짜 버그로 착각하지 않습니다.

API 응답을 모의로 만드는 방법

03 테스트

검사하고, 같은 검사를 CI에서 실행하세요

엔드포인트에 검사를 추가하세요: 상태, 시간, 필드, 헤더 또는 JSON Schema. 저장된 요청을 엮어 스위트로 만들 수도 있습니다. 내려받을 수 있는 명령줄 도구가 파이프라인에서 이를 실행하고, 검사가 실패하면 빌드를 실패시킵니다. 캐싱과 압축에 대한 조언, 그리고 응답이 지난번과 같은지 확인하는 검사도 받을 수 있습니다.

컬렉션은 Postman, Insomnia, Bruno, Hoppscotch, Thunder Client, OpenAPI 3, Swagger 2, WSDL, HAR, cURL에서 가져옵니다. 내보낼 때는 Postman 컬렉션, Bruno·Insomnia·Hoppscotch용 컬렉션, OpenAPI 3.0, API 문서 페이지, 15개 언어의 코드, 또는 Playwright, Cypress, k6, JMeter, Gatling, Locust 스크립트로 나갑니다.

API 검사를 CI에서 실행하는 방법

04 AI 도구

AI 없이, AI 도구를 테스트하세요

RequestFox는 어떤 AI 모델도 실행하지 않습니다. 직접 만드는 AI 도구를 테스트합니다. '작성'은 MCP 서버에 연결해 그 도구를 호출하고, 언어 모델 API로 보낸 호출에서는 모델, 응답이 알려 주는 토큰 수, 중지 이유, 시간을 보여 줍니다.

'MCP 제어'를 켜면(기본값은 꺼짐) 내 컴퓨터의 AI 에이전트가 RequestFox를 통해 기록하고, 다시 보내고, 모의 응답을 만들 수 있습니다. 모든 보내기와 다시 보내기는 사용자의 클릭을 기다립니다.

'MCP 제어'가 안전한 이유

로컬 MCP 클라이언트가 제어 중

이 MCP 작업을 허용할까요?

로컬 MCP 클라이언트가 다음을 요청합니다: 보내기 POST shop.example.com/api/orders. 허용하지 않으면 아무 일도 일어나지 않습니다.

취소허용

Alt Shift S를 누르고 앱을 쓰세요.

모든 fetch, XMLHttpRequest, WebSocket 프레임, 서버 전송 이벤트가 시작되는 순간 나타납니다. 탭, 프레임, 팝업을 넘나들어도, 서비스 워커가 응답한 호출이라도 마찬가지입니다.

각 호출은 그것을 일으킨 클릭이나 폼 제출과 연결되고, 각 세션은 다음 세션과 비교할 수 있도록 '내역'에 보관됩니다.

Mac에서는 Option Shift S입니다. 또는 사이드 패널을 열고 '기록 시작'을 누르세요. API 호출을 단계별로 기록하는 방법

QA 테스터, 프런트엔드 개발자, API 개발자를 위해 썼습니다. 모든 가이드에는 OpenAPI 스펙에 맞춰 호출을 검사하는 방법도 있습니다.

자주 묻는 질문

RequestFox는 무료인가요?

네. RequestFox는 무료이며, 저희의 약속을 여기에 적어 둡니다: 오늘 무료로 쓸 수 있는 것은 나중에도 유료로 바뀌지 않습니다. 광고도, 계정도, 유료 요금제도 없습니다.

RequestFox가 제 데이터를 어딘가로 보내나요?

아니요. RequestFox가 기록하는 모든 것은 사용자 기기의 브라우저 저장소에 남습니다. RequestFox 서버도, 분석도, 계정도 없습니다. RequestFox가 보관하거나 로그로 남기거나 내보내는 모든 것에서 Authorization 헤더, 쿠키, 비밀 값처럼 보이는 필드는 기본적으로 가려집니다('작성'은 내 요청에 대한 응답을 받은 그대로 보여 줍니다. 그 '최근' 목록은 최근 보낸 요청 100개를 가린 상태로 이 기기에 보관하며, '지우기'를 누를 때까지 남습니다). 사이트 접근 권한은 '기록 시작'을 누를 때, 또는 관련 사이트에 한해 '작성'에서 보내거나 기록 중이 아닐 때 테스트 스위트를 실행할 때만 요청합니다.

RequestFox는 AI를 사용하나요?

아니요. RequestFox는 어떤 AI 모델도 실행하지 않습니다. 직접 만드는 AI 도구는 테스트할 수 있습니다: MCP 서버, 그리고 페이지가 언어 모델 API로 보내는 호출입니다. 'MCP 제어'를 켜면(기본값은 꺼짐) 내 컴퓨터의 AI 에이전트가 RequestFox를 조작할 수 있으며, 모든 보내기는 사용자의 클릭을 기다립니다.

브라우저에서 동작하는 무료 Postman 대안이 있나요?

RequestFox는 무료 브라우저 확장 프로그램입니다. 환경, {{변수}}, OAuth 2.0을 포함한 인증 도우미, 저장된 컬렉션으로 요청을 작성해 보내고, Postman, Insomnia, Bruno, Hoppscotch, Thunder Client 컬렉션을 가져오며, Postman 컬렉션과 Bruno·Insomnia·Hoppscotch용 컬렉션을 내보냅니다. 독립 실행형 클라이언트와 달리 웹 앱이 실제로 보내는 호출도 기록합니다. 클라우드 작업 공간이나 팀 동기화는 없습니다.

RequestFox는 DevTools의 Network 패널과 무엇이 다른가요?

DevTools는 모든 요청을 보여 주고 판단은 사용자에게 맡깁니다. RequestFox는 실패, 느림, 중복, 재시도 호출에 발생하는 순간 플래그를 붙이고, 각 호출을 그것을 일으킨 클릭과 연결하며, 엔드포인트별 규칙을 검사하고, 모든 세션을 보관해 오늘의 실행을 어제와 비교할 수 있게 합니다. 페이지가 불러오는 모든 것을 날것 그대로 실시간으로 보려면 DevTools가 더 낫습니다.

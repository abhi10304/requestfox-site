Debug the API calls your UI makes

RequestFox shows every call your app makes with the click and the page functions behind it, flags double fetches, N+1 bursts and slow endpoints, and lets you mock loading, empty and error states in place. It runs beside your app, in the browser you already debug in.

For RequestFox 2.5.0, checked 19 November 2026.

Why did that call fire?

Every call is tied to the click or form submit that caused it. Details shows "Called from", the page functions that made it, plus the timing split (DNS, connect, TLS, waiting, download).

Find wasted calls

  • Duplicate · after 140 ms the same request twice in a moment, often an effect that runs twice.
  • One call per item N+1: a call for each item in a list, where one batched call would do.
  • Performance lists the heaviest endpoints; the Timeline shows what waited on what.

See every UI state without touching the backend

Mock an empty list, an error, a slow response or a dropped connection, then check your loading, empty and error screens. Need to change a call in flight? Pause it with a breakpoint and edit it on the way. How to mock an API response.

GraphQL, streams and sockets

GraphQL calls are told apart by operation, and errors inside a 200 OK are flagged. Load the schema and recorded calls are checked against it. Server-sent events and token streams (read with fetch, XMLHttpRequest or EventSource) show their events live, with error events, a missing end marker and long pauses flagged, and WebSocket frames are listed with the calls. To see how a page copes, rewrite a response with a script or slow the whole tab down (both Chrome), or make an endpoint fail with a mock set that stays on.

A worked example: a search box that asks twice

Say you type "boots" into a search box and the results flicker. In RequestFox, GET /api/search?q=boots shows twice, and the second card carries Duplicate · after 140 ms. Press "Why is this flagged?": "The same call was made again within moments: often a double click or a double render." Its next step: make the page send the call once, and use Repeats on the card to see each copy and what started it.

Open Details on one copy: "Called from" lists the page functions that made the call, so you know where to look in your code. Often it's an effect that runs twice. Fix it and search again: one card means the double fetch is gone. Want to see how the results list looks while the response is slow? Mock a slow response for that endpoint.

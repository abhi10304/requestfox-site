How to intercept and modify API calls in Chrome

Chrome DevTools can already do part of it: override a response with a local file, block a request, and resend a request you edit as a fetch() call [1][2]. A browser extension adds a faster route. In RequestFox, a browser extension for Chrome and Firefox, record the call, press Mock on its card, change the status or body and press Mock it; the page then gets your response. To change a request, use Edit and send again… in its card's More menu. Details and limits below.

For RequestFox 2.5.0, checked 19 November 2026. Facts about Chrome are from its own documentation, checked 20 November 2026; sources below.

Can Chrome DevTools intercept and change an API call?

  • Change a response: right-click the request in the Network panel and choose Override content or Override headers. DevTools saves a copy of the file in a folder you choose and serves it on reload [1].
  • Resend a request: Edit and resend as fetch opens the Console with the request written as a fetch() call; change it and press Enter [2]. Since Chrome 152 the old Replay XHR item is called Resend, and it handles every fetchable request [3].
  • Block a request: the Network request blocking tab in the drawer [2].

Overrides turn the browser cache off while they are enabled, and the changes are files you manage in a folder [1].

How do I change a response with RequestFox?

  1. Record the real call

    Press Start Recording and do what makes the call.

  2. Press Mock on its card

    Open the card and press Mock. The dialog holds the status and body the server sent.

  3. Change it and press Mock it

    Edit the status or body, then press Mock it. Reload the page: it gets your response, and the card says Mocked.

To make a call fail, slow or pause instead, add a rule under Settings: modes include Network error, Slow and a breakpoint on the request or the response. Mock an API response has every step, and Change a request header covers headers and addresses.

How do I change a request and send it again?

Open the call's card, open its More menu and choose Edit and send again…. Change the method, address, headers or body, and send. The edited call is a new card at the top of the log, and the link Compare with the original sets the two side by side. Replay and edit a request has the details.

Which one should I use?

  • A quick change to one file, with nothing to install: DevTools overrides.
  • An error, an empty list or a slow response to test a screen: a RequestFox mock, labelled so nobody files it as a bug.
  • A request you want to tweak and compare: Edit and send again…, or DevTools' Edit and resend as fetch.

A mock does not answer calls from a worker, images or scripts, and it is for calls the page makes itself. RequestFox vs the DevTools Network panel has the rest.

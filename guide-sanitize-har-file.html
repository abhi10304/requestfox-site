How to clean a HAR file before you share it

A HAR file is a copy of what your browser sent and received, so it can hold cookies, tokens and passwords. Chrome's Export HAR (sanitized)… leaves out the Cookie, Set-Cookie and Authorization headers [1]; read the file for anything else. To clean any HAR file, open it in RequestFox, a browser extension for Chrome and Firefox: in History press Open file…, then use the session's More menu, choose HAR and press Export with secrets hidden. The dialog names what was removed.

For RequestFox 2.5.0, checked 19 November 2026. Facts about browsers are from their own documentation, checked 20 November 2026; sources below.

What is in a HAR file?

Every request and response the Network panel held when you saved it: addresses, headers, bodies and timing. That includes anything you typed or were given while the panel was open: a sign-in form's password in a request body, a session cookie, a bearer token in a header, a token in an address. Whoever gets the file can read all of it, and a token that has not expired can be used.

Does Chrome sanitize a HAR file?

Yes, by default. The Network panel's Export HAR (sanitized)… and Save all as HAR (sanitized) omit sensitive data such as the Cookie, Set-Cookie and Authorization headers [1]. To get those back, turn on Allow to generate HAR with sensitive data in Settings, Preferences, Network, and then choose Export HAR (with sensitive data) [1].

The docs name headers. A token in an address, a password in a request body or a card number in a response is a different place, so read the file before you send it. Firefox's Save All As HAR is described in its own docs [2]; do not assume it is cleaned, and clean it as below.

How do I clean a HAR file with RequestFox?

  1. Open the file

    In RequestFox press History, then Open file… and pick the .har file. While Hide passwords, tokens and card numbers in what is recorded is on in Settings (it is on by default), the tokens, passwords and cookies in it are hidden as it opens. The File opened dialog lists what was hidden, by kind.

  2. Export it as HAR

    On the session, open More and choose HAR. A recording of your own works the same way from Export, bottom right.

  3. Choose to hide the secrets

    If the session still holds a token, a cookie or a password, a dialog titled This file will contain secrets asks first. Its main button, Export with secrets hidden, is the one to press. The question ends with what that export removes: a count of tokens, cookies, passwords, card numbers and file names. Export as it is keeps them.

  4. Send the new file

    The HAR you save has the hidden values written as ***REDACTED***. Keep the original file private.

An export saved when you press Stop is always the hidden copy.

What should I still check?

  • RequestFox hides what looks like a token, cookie, password or card number. A secret written in plain words in a body cannot be told apart from other text, so skim the calls that sign in or pay.
  • Personal data is not a secret in this sense. Email addresses, names and ids in responses stay; the Security mark on a card can point at some of them while you record.

To read a file without exporting it, see how to open a HAR file.

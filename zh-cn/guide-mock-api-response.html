如何在没有后端的情况下模拟 API 响应

RequestFox 是一个浏览器扩展程序，无需后端就能模拟 API 响应：打开一个录制的调用，在它的卡片上点“模拟”，需要的话改一下状态码或响应体，再点“模拟”，然后重新加载页面。从此以后，页面通过 fetch 和 XMLHttpRequest 发出的调用会收到你的响应，而不是服务器的响应，调用上会标着“已模拟”。Chrome DevTools 的本地替换（local overrides）和 Mock Service Worker 是另外两种方式，下面有对比。

适用于 RequestFox 2.5.0，核对于 2026年11月19日。

步骤

  1. 先录制一次真实调用

    点 开始录制，然后执行会触发这个调用的操作，让 RequestFox 拿到它真实的状态码、响应头和响应体作为起点。

  2. 在卡片上点“模拟”

    打开这个调用的卡片，点 重放 旁边的 模拟。对话框里是服务器发回的响应：它的状态码和响应体。对一个根本没收到响应的调用（后端挂了）也可以用：这时从 200 和 {} 开始。

  3. 修改响应，然后模拟

    把状态码或响应体改成你想测试的内容：一个空列表、一个错误、一个缺失的字段。点 模拟。更多选项… 会打开完整的规则（方法、地址如何匹配、内容类型、GraphQL 操作）。

  4. 再触发一次调用

    重新加载页面，或在页面里再做一次那个操作。页面会收到你的响应，卡片上显示 已模拟，这样就没人会把它当成 bug 报上来。重放 和 撰写 始终调用真实服务器，所以要用页面本身来查看模拟效果。

模拟没有生效时

再次打开这个调用：如果模拟没有响应它，卡片会用下面这些话说明原因。

  • 卡片上写着：未模拟：它的模拟已关闭。在卡片上点 模拟已关闭，再点 开启。
  • 未模拟：页面在 RequestFox 准备好之前发出了此请求。请再重新加载一次页面。页面最早的几个调用可能在 RequestFox 准备好之前就发出了；再重新加载一次，模拟就会响应它们。
  • 未模拟：此请求不是页面本身发出的（Worker、Beacon 或 RequestFox 无法进入的框架），所以模拟无法响应它。如果页面自己发出了对应的调用，就改为模拟那个调用。
  • 你点了“重放”，或从“撰写”发送了它：未模拟：“重放”和“撰写”始终调用真实服务器。请使用页面本身。
  • 没有在录制，模拟也没有设为保持开启：卡片上写着 模拟已暂停。点 开始录制，或让它保持开启（见下文）。
  • 页面还显示旧数据：重新加载它。模拟只响应下一次调用，不会响应页面已经发出的调用。

不录制时也保持模拟开启

在卡片上点 已模拟，再点 不录制时也保持开启…，然后填写网站（例如 localhost）。之后模拟会在这个网站的每个标签页里响应，无需录制，直到你关闭它；顶栏下方会有一个标签写着模拟集已开启：localhost，后面是这组模拟的名称。

模拟一个从未录制过的调用

设置 → 模拟与规则 → 模拟或故意破坏端点 → 添加规则…，模式选“模拟”：输入要匹配的地址片段、状态码和响应体。

改为破坏一个调用

设置 → 模拟与规则 → 模拟或故意破坏端点 → 添加规则…。填写要匹配的地址片段、一个方法和一种模式：

  • 失败：用你选的错误状态码响应。
  • 网络错误：像连接断开那样失败。
  • 缓慢或限速：加一段延迟，或按响应大小减慢它。
  • 模拟：返回你写的响应。
  • 断点（请求）或断点（响应）：暂停这个调用，让你在它继续之前修改它。
  • 循环：每次调用返回不同的响应。

你故意破坏的调用会标着“注入故障”。

完成之后

调用的卡片上写着“已模拟”：点它可以编辑响应、不录制时也保持开启、关闭或删除这个模拟。点“停止”之后，它会写着“模拟已暂停”：模拟会等下一次录制。只要有规则开着，录制栏就会显示“模拟已开启（n）”；点它可以看到所有规则。模拟只在 RequestFox 录制该标签页时响应（除非你让它在不录制时也保持开启），而且只响应页面用 fetch 或 XMLHttpRequest 发出的调用（不包括 Worker 的调用、图片或脚本）。

DevTools 本地替换、Mock Service Worker 还是扩展程序？

在浏览器里改变 API 调用返回内容的三种方式，并排对比。本地替换是 Chrome DevTools 的一部分，无需安装任何东西。Mock Service Worker 是你加进自己应用里的一个库。像 RequestFox 这样的扩展程序在任何网站上都能用，并从它录制的调用出发。

バックエンドなしで API レスポンスをモックする方法

RequestFox は、バックエンドなしで API レスポンスをモックできるブラウザー拡張機能です。記録した呼び出しを開いてカードの「モック」を押し、必要ならステータスや本文を変えて「モックする」を押し、ページを再読み込みします。以後、ページが fetch と XMLHttpRequest で行う呼び出しには、サーバーのレスポンスの代わりにあなたのレスポンスが返り、その呼び出しには「モック済み」のラベルが付きます。Chrome DevTools のローカル オーバーライドと Mock Service Worker は別の 2 つの方法で、下で比べています。

RequestFox 2.5.0 対応、2026年11月19日 に確認。

手順

  1. 本物の呼び出しを一度記録する

    記録を開始 を押し、その呼び出しが起きる操作をします。これで RequestFox は、本物のステータス、ヘッダー、本文を出発点として持てます。

  2. カードの「モック」を押す

    呼び出しのカードを開き、リプレイ の隣の モック を押します。ダイアログには、サーバーが返したレスポンス（ステータスと本文）が入っています。レスポンスがまったく返らなかった呼び出し（バックエンドが落ちている）にも使えます。その場合は 200 と {} から始まります。

  3. レスポンスを変えてからモックする

    ステータスや本文を、テストしたい内容に変えます。空のリスト、エラー、欠けたフィールドなどです。モックする を押します。その他のオプション… では、ルール全体（メソッド、アドレスの照合方法、コンテンツ タイプ、GraphQL のオペレーション）を開けます。

  4. もう一度呼び出させる

    ページを再読み込みするか、ページで同じ操作をもう一度します。ページにはあなたのレスポンスが返り、カードには モック済み と表示されるので、誰もバグとして報告しません。リプレイ と 作成 は常に実際のサーバーを呼び出すので、モックはページ自体で確かめてください。

モックが応答しないとき

呼び出しをもう一度開きます。モックが応答しなかった場合、カードにはその理由が次の言葉で表示されます。

  • カードの表示：モックされていません：このモックはオフです。 カードの モックオフ を押し、オンにする を押します。
  • モックされていません：RequestFox の準備ができる前にページがこの呼び出しを行いました。もう一度ページを再読み込みしてください。 ページのごく最初の呼び出しは、RequestFox の準備ができる前に来ることがあります。もう一度再読み込みすれば、モックが応答します。
  • モックされていません：この呼び出しはページ自身が行ったものではありません（ワーカー、ビーコン、RequestFox が届かないフレーム）。そのためモックは応答できません。 ページ自身が行う呼び出しがあれば、代わりにそちらをモックします。
  • 「リプレイ」を押したか、「作成」から送った場合：モックされていません：「リプレイ」と「作成」は常に実際のサーバーを呼び出します。 ページ自体を使ってください。
  • 何も記録しておらず、モックも有効のままにしていない場合、カードには モック一時停止中 と表示されます。記録を開始 を押すか、有効のままにします（下記）。
  • ページにまだ古いデータが表示される場合は、再読み込みします。モックが応答するのは次の呼び出しで、ページがすでに行った呼び出しではありません。

記録なしでもモックを有効にしておく

カードで モック済み を押し、記録なしでも有効にする… を押して、サイト名を入れます（例：localhost）。するとモックは、オフにするまで、何も記録せずにそのサイトのすべてのタブで応答します。上部バーの下のチップにモックセット有効：localhostとセット名が表示されます。

一度も記録していない呼び出しをモックする

設定 → モックとルール → エンドポイントをモックする・壊す → ルールを追加… で、モードを「モック」にします。照合するアドレスの一部、ステータス、本文を入力します。

代わりに呼び出しを壊す

設定 → モックとルール → エンドポイントをモックする・壊す → ルールを追加…。照合するアドレスの一部、メソッド、モードを指定します。

  • 失敗：選んだエラー ステータスで応答します。
  • ネットワークエラー：接続が切れたときと同じように失敗します。
  • 低速 または スロットル：遅延を加えるか、レスポンスをサイズに応じて遅くします。
  • モック：書いたレスポンスを返します。
  • ブレークポイント（リクエスト） または ブレークポイント（レスポンス）：呼び出しを一時停止し、先へ進む前に編集できるようにします。
  • 循環：呼び出しごとに違う応答をします。

わざと壊した呼び出しには「シミュレーション」のラベルが付きます。

終わったら

呼び出しのカードには「モック済み」と表示されます。押すと、レスポンスの編集、記録なしでも有効にする、オフにする、モックの削除ができます。「停止」の後は「モック一時停止中」と表示され、モックは次の記録を待ちます。ルールが 1 つでもオンの間は、記録バーに「モック有効（n）」と表示されます。押すとすべてのルールが見られます。モックが応答するのは、RequestFox がそのタブを記録している間だけ（記録なしでも有効にした場合を除く）で、ページが fetch か XMLHttpRequest で行う呼び出しだけです（ワーカーの呼び出し、画像、スクリプトは対象外）。

DevTools のローカル オーバーライド、Mock Service Worker、それとも拡張機能？

ブラウザーで API 呼び出しの返す内容を変える 3 つの方法を並べました。ローカル オーバーライドは Chrome DevTools の一部なので、インストールは不要です。Mock Service Worker は自分のアプリに追加するライブラリです。RequestFox のような拡張機能はどのサイトでも動き、記録した呼び出しから始められます。

どの API 呼び出しが失敗したかが分かります。

ログイン不要、オフラインで動作。RequestFox は、Chrome と Firefox のサイドパネルで動く無料の API テスター兼ネットワークモニターです。Web アプリが行うすべての呼び出しを記録し、壊れた呼び出しにはその瞬間にフラグを付け、リプレイ、モック、テストができます。

Chrome に追加（無料） Firefox に追加

アカウント不要。私たちには何も送られません。AI は入っていません。

RequestFox の立ち位置

これらの API テストツールには、それぞれ最適な用途があります。Web アプリをテストしていて、API の問題を起きたその瞬間に見つけてほしいなら、RequestFox を選んでください。

DevTools Network

Postman, Insomnia, Bruno, Hoppscotch

アプリが実際に送るものを記録し、何が壊れたかを伝え、あなたのリクエストも送信します。

どの作業にどのツールか

  • Web アプリをテストし、問題を見つけてほしいとき

    RequestFox。クリックに合わせて呼び出しを記録し、失敗したもの、遅れたもの、2 回送られたもの、200 OK の中で壊れたものにフラグを付け、すべてのセッションを保存します。

  • 1 回のページ読み込みで起きることを、そのまま見たいとき

    DevTools の Network パネル。ブラウザーに組み込まれています。絞り込みと読み取りはあなたが行います。RequestFox と DevTools の比較

  • チームで API を設計し、文書化し、共有するとき

    Postman または Insomnia。RequestFox はどちらからもインポートでき、どちらへもエクスポートできます。RequestFox と Postman の比較 · RequestFox と Insomnia の比較

  • リクエストをプレーンなファイルとして Git でコードの隣に置きたいとき

    Bruno。Chrome では、RequestFox もコレクションをリンクしたフォルダーにファイルとして保存できます。RequestFox と Bruno の比較

  • 自分でホストできる、Web 上のオープンソースクライアントがほしいとき

    Hoppscotch。RequestFox にはホストするものがありません。サーバーがないからです。RequestFox と Hoppscotch の比較

RequestFox が及ばないところ

  • RequestFox が見るのはブラウザーのタブが送るものです。モバイルアプリやデスクトップアプリには、HTTP Toolkit、Proxyman、Charles などのプロキシツールが必要です。
  • チームのワークスペースやクラウド同期は、意図してありません。作業はファイルで共有してください：コレクション、セッション、HAR、レポート。
  • スクリプトは Chrome でのみ動きます。Firefox は、実行時に入力されたコードを拡張機能が実行することを許可していません。
  • ネイティブの gRPC クライアントや MQTT クライアントはありません（gRPC-Web と Connect のみ）。

どの問題にも、分かりやすい名前

呼び出しは終わった時点で判定されます。フラグを選ぶと、パネルがそれについて何を伝えるかを読めます。

フラグ

POST /api/orders 500 412 ms

フラグが付いた理由

サーバーが応答中に失敗しました（5xx ステータス）。

対処：その時刻のサーバーログを確認してください。「リプレイ」で同じリクエストをもう一度送り、再現するか確かめられます。

GET /api/search?q=boots 200 3.1 s

フラグが付いた理由

レスポンスに、設定した低速の上限より長い時間がかかりました。

対処：詳細のタイミングで時間の内訳が分かります。上限は設定にあります。

POST /graphql 200 96 ms

フラグが付いた理由

HTTP ステータスは OK ですが、レスポンスには呼び出しが失敗したと書かれています。

対処：レスポンス内のエラーを読んでください。ステータスだけではこの失敗は見えません。

GET /api/me 401 54 ms

フラグが付いた理由

呼び出しが拒否され、送ったトークンはすでに期限切れでした。

対処：もう一度サインインするかトークンを更新してから、呼び出しを送り直してください。

GET /api/cart 200 120 ms

フラグが付いた理由

レスポンスの形（フィールドとその型）が、以前この呼び出しが返したものと違います。

対処：カードの形の差分を開いて、何が変わったか確認してください。

GET /api/stock/42 503 230 ms

フラグが付いた理由

この呼び出しは記録したセッションによって失敗したり成功したりしています。

対処：履歴で失敗したレスポンスと成功したレスポンスを比べてください。

RequestFox が付けるすべてのフラグ

フラグから修正まで

01 リプレイ

そのまま送り直すか、先に編集する

記録した呼び出しをそのままもう一度送るか、「作成」で変更します。環境、{{変数}}、デバイスコード対応の OAuth 2.0、OAuth 1.0a、JWT Bearer、AWS Signature v4 を内蔵し、複数のリクエストを同時に開いておけます。

リクエストやコレクションに保存済みの例やメモを残せます。サイトごとにオンにする Cookie ストアがサインイン状態を次の送信に引き継ぎ、WebSocket クライアントには Socket.IO モードがあります。

リクエストをリプレイ・編集する方法

02 モック

モックする、壊す、遅くする

呼び出しを開いて「モック」を押すと、実際のステータスと本文がそのまま編集できる状態で表示されます。「モックする」を押してページを再読み込みすると、ページにはあなたのレスポンスが返ります。ルールを使えば、バックエンドに触れずに呼び出しを失敗させたり、遅くしたり、一時停止したりもできます。ルールセットとモックセットは、必要なときにオンのままにしておけます。

Chrome では、タブ全体を遅くしたり、スクリプトでリクエストやレスポンスを書き換えたりもできます。変更した呼び出しには モック済み または シミュレーション のラベルが付くので、本物のバグと取り違えることはありません。

API レスポンスをモックする方法

03 テスト

チェックして、同じチェックを CI で実行する

エンドポイントにチェックを追加します：ステータス、時間、フィールド、ヘッダー、JSON Schema。保存済みのリクエストをつなげてスイートにもできます。ダウンロードできるコマンドラインツールがパイプラインでそれらを実行し、チェックが失敗するとビルドを失敗させます。キャッシュと圧縮についてのアドバイスや、レスポンスが前回と同じままかどうかのチェックも得られます。

コレクションは Postman、Insomnia、Bruno、Hoppscotch、Thunder Client、OpenAPI 3、Swagger 2、WSDL、HAR、cURL から取り込めます。書き出しは Postman コレクション、Bruno・Insomnia・Hoppscotch 向けのコレクション、OpenAPI 3.0、API ドキュメントページ、15 言語のコード、または Playwright、Cypress、k6、JMeter、Gatling、Locust のスクリプトです。

API チェックを CI で実行する方法

04 AI ツール

AI ツールをテスト、AI は使わずに

RequestFox は AI モデルを一切動かしません。あなたが作る AI ツールをテストします：「作成」は MCP サーバーに接続してそのツールを呼び出し、言語モデル API への呼び出しでは、モデル、レスポンスが示すトークン数、停止理由、時間が表示されます。

「MCP コントロール」をオンにすると（既定ではオフ）、あなた自身のコンピューター上の AI エージェントが RequestFox を通じて記録、リプレイ、モックを行えます。送信とリプレイは毎回あなたのクリックを待ちます。

「MCP コントロール」が安全である理由

ローカルの MCP クライアントが操作中

この MCP 操作を許可しますか？

ローカルの MCP クライアントが次を求めています：送信 POST shop.example.com/api/orders。許可しない限り何も起こりません。

キャンセル許可

Alt Shift S を押して、あとはアプリを使うだけ。

fetch、XMLHttpRequest、WebSocket のフレーム、サーバー送信イベントは、どれも始まった瞬間に表示されます。タブ、フレーム、ポップアップをまたいでも、Service Worker が応答した呼び出しでも同じです。

各呼び出しは、それを起こしたクリックやフォーム送信に結び付けられ、各セッションは次回と比べられるよう「履歴」に保存されます。

Mac では Option Shift S です。または、サイドパネルを開いて「記録を開始」を押します。API 呼び出しを記録する手順

QA テスター、フロントエンド開発者、API 開発者のために書きました。すべてのガイドには、OpenAPI 仕様に照らして呼び出しをチェックする方法もあります。

よくある質問

RequestFox は無料ですか？

はい。RequestFox は無料です。そして約束をここに書いておきます：今日無料で使えるものが、あとから有料になることはありません。広告も、アカウントも、有料プランもありません。

RequestFox はデータをどこかに送りますか？

いいえ。RequestFox が記録したものはすべて、あなたのデバイス上のブラウザーのストレージに残ります。RequestFox のサーバーも、アクセス解析も、アカウントもありません。RequestFox が保存、ログ出力、エクスポートするものすべてで、Authorization ヘッダー、Cookie、秘密情報らしいフィールドは既定でマスクされます（「作成」は自分のリクエストへのレスポンスを届いたとおりに表示します。その「最近の送信」の一覧は直近 100 件の送信をマスクした状態でこのデバイスに保持し、「クリア」を押すまで残ります）。サイトへのアクセスを求めるのは、「記録を開始」を押したとき、または関係するサイトについて、「作成」から送信したときや、何も記録していない状態でテストスイートを実行したときだけです。

RequestFox は AI を使っていますか？

いいえ。RequestFox は AI モデルを一切動かしません。あなたが作る AI ツールをテストすることはできます：MCP サーバーや、ページが言語モデル API に対して行う呼び出しです。「MCP コントロール」をオンにすると（既定ではオフ）、あなた自身のコンピューター上の AI エージェントが RequestFox を操作でき、送信は毎回あなたのクリックを待ちます。

ブラウザーで動く無料の Postman 代替はありますか？

RequestFox は無料のブラウザー拡張機能です。環境、{{変数}}、OAuth 2.0 などの認証ヘルパー、保存済みコレクションを使ってリクエストを作成・送信でき、Postman、Insomnia、Bruno、Hoppscotch、Thunder Client のコレクションをインポートし、Postman コレクションと Bruno・Insomnia・Hoppscotch 向けのコレクションをエクスポートします。単体のクライアントと違い、Web アプリが実際に行う呼び出しも記録します。クラウドのワークスペースやチーム同期はありません。

RequestFox は DevTools の Network パネルと何が違いますか？

DevTools はすべてのリクエストを表示し、判断はあなたに任せます。RequestFox は失敗、低速、重複、再試行の呼び出しに起きた時点でフラグを付け、それぞれを引き起こしたクリックに結び付け、エンドポイントごとのルールをチェックし、すべてのセッションを保存するので、今日の実行と昨日の実行を比べられます。ページが読み込むものすべてをそのままライブで見るなら、DevTools のほうが向いています。

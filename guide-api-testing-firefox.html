API testing in Firefox: what is built in and which extensions help

Firefox can already test an API call with no add-on: in the Network Monitor, choose Edit and Resend on a request, change its method, address, headers or body, and send it again. For more than that, add a Firefox extension. RESTer and RESTED are REST clients: you write each request by hand. RequestFox is a browser extension that records the calls your web app makes and flags the ones that went wrong.

For RequestFox 2.5.0, checked 19 November 2026. Facts about Firefox and other add-ons are from their own pages, checked 4 November 2026; sources below.

What can Firefox do on its own?

Firefox's Network Monitor lists the requests a page makes, and a request you pick can be sent again without any add-on [1][2]:

  • Resend sends the request again as it was [1][2].
  • Edit and Resend opens an editor where you change the method, address, headers or body, then press Send [1].
  • Copy offers the request as a cURL command or as a fetch() call [2].
  • Save All As HAR writes the listed requests to a HAR file [2].
  • Block URL blocks the chosen address for later requests [2].

It's the quickest way to try one call you can already see. It works one request at a time, though, and deciding which calls went wrong is up to you. The extensions below add more.

Which Firefox extensions test APIs?

These four are REST clients: you write a request and send it. The words in quotes are each listing's own summary, and the dates are the last update shown on Firefox Add-ons. They're listed in no order of merit.

A client is the right tool when you already know which request to send. RequestFox starts from the other end: it watches what your web app actually sends, so there's nothing to retype.

How do I record the API calls a page makes in Firefox?

  1. Add RequestFox from Firefox Add-ons. There's no account to make.
  2. Open the site you want to test. Open RequestFox's sidebar and press Start Recording (or press Alt Shift S; Option Shift S on a Mac). The first time, Firefox asks you to allow access to the site.
  3. Use the page. Every fetch, XMLHttpRequest, WebSocket frame and server-sent event is listed as it starts, tied to the click or form submit that caused it.
  4. Read the flags. A call that failed, was slow, fired twice or hid an error inside a 200 OK is marked, and its card says why in plain words.
  5. Press Replay to send a call again, or choose Edit and send again… in its ··· menu to change it first. While recording, the call goes through the page, with its cookies.

The full steps, with the search box and what to do when nothing shows up, are in How to record API calls. Sessions stay in History, and you can export them as a HAR file, a Postman collection or an HTML report.

What does RequestFox not do in Firefox?

  • Scripts that run before a request or after a response, and rewriting a request or response with a script, work in Chrome only: Firefox does not let extensions run code typed at runtime. Chaining values from one request to the next works in both.
  • Firefox has no debugger API for extensions, so there is no slow-down for the whole tab. Use a mock rule's Slow or Throttle mode for one endpoint instead.
  • Clicking a RequestFox notification opens the sidebar in the window you're looking at, which may not be the window being recorded.
  • It sees what a browser tab sends. Mobile and desktop apps need a proxy tool such as HTTP Toolkit, Proxyman or Charles, and there is no team workspace or cloud sync: share work as files.

Apart from these, recording, flags, mocks, checks and exports work the same in Firefox as in Chrome. The feature list says which feature is Chrome only.

Which one should I use?

  • To try one call you can already see: Edit and Resend in the Network Monitor. Nothing to install.
  • To write requests by hand and keep them: a REST client such as RESTer or RESTED.
  • To test your own web app as you click through it, with the broken calls found for you: RequestFox.

They fit together. Record in RequestFox, and use the built-in tools for a quick look at one request.

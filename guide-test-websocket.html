How to test a WebSocket or Socket.IO server in the browser

Open WebSocket / SSE activity in RequestFox, a browser extension for Chrome and Firefox, type the server's ws:// or wss:// URL under Open a connection and press Connect. Type a message and press Send; what the server sends back shows below, each line marked Received or Sent. For a Socket.IO server, pick Socket.IO beside the URL: RequestFox joins the namespace, answers the pings for you, and sends events with Emit. If the connection closes, it says the close code and what it means.

For RequestFox 2.5.0, checked 17 November 2026.

How do I connect to a WebSocket server?

  1. Open WebSocket / SSE activity

    In RequestFox, press WebSocket / SSE activity in the top bar. Open a connection is the box at the bottom.

  2. Type the URL and press Connect

    Type the server's address, such as wss://api.example.com/socket; {{variables}} work in it. Press Connect. The line under it says Connecting…, then which server you are connected to.

  3. Add a header or subprotocol if the server needs one

    Headers (optional) go with the handshake in Chrome and Firefox, such as Authorization: Bearer {{token}}; the browser may ask you to allow RequestFox on that site. Subprotocol (optional) takes names separated by commas.

  4. Send a message

    Type it and press Send. Send as picks Text, Binary (base64) or Binary (hex). Save message keeps one to send again later.

  5. Read what came back

    Each line says Received or Sent. Filter messages narrows the list, and Copy log copies it for a bug report. Tick Reconnect if it drops for RequestFox to try again after a drop, up to five times.

Need a second socket at the same time, such as two users in one chat? Press New connection: up to five connections stay open side by side, each with its own URL, headers and log.

How do I test a Socket.IO server?

A Socket.IO server speaks its own protocol on top of WebSocket (a handshake, pings, namespaces and events), so pick Socket.IO in the list beside the URL instead of WebSocket; an http:// or https:// address works too. Then set the Path (usually /socket.io/), the Namespace, the Server version (v3 / v4, or v2 for an older server) and, if the server checks one, the Auth payload (JSON, optional).

After Connect, type an Event name and its Arguments (JSON), tick Wait for ack if the server answers the event, and press Emit. RequestFox answers the server's pings itself and keeps them out of the way until you press Show pings. It talks Socket.IO over WebSocket only: long-polling isn't supported.

Can I see the sockets my web app opens?

Yes. Press Start Recording and use the page: every WebSocket and server-sent events connection it opens shows under Recorded activity, with each message. A connection the page opened before you pressed Start is not seen: reload the page. Socket.IO frames read as events with their arguments; Raw frames shows them as sent. While recording, Inject a message pushes a message into the page's open connection, as if the server had sent it.

What if it does not connect?

  • "Couldn't connect": check the URL and that the server is running. A WebSocket address starts with ws:// or wss://.
  • "The server answered HTTP 401" (or 403, 404) to the handshake: the URL is wrong, or the server wants a token or a sign-in. Add the header it expects, or for Socket.IO the auth payload.
  • It closes with a code. RequestFox says what the code means: 1006 is a drop with no close message (network, proxy or server crash), 1008 is refused by the server's rules (often sign-in), 1011 is a server error.
  • Socket.IO never joins. Check that the server runs Socket.IO and that Server version matches it.
  • The headers could not be added. Allow RequestFox on that site when the browser asks, then press Connect again: nothing is sent without them.

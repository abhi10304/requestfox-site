How to import a Postman collection and run it in the browser

Export the collection from Postman as a JSON file, then in RequestFox, a browser extension for Chrome and Firefox, open Compose → Import → Import a collection… and pick the file. RequestFox saves it under Saved collections: a file with folders becomes one folder named after the file, its folders kept, with their variables and auth. It turns the common tests (status, time, header and JSON field checks, and saved values) into checks and chaining rows, and lists every script it couldn't turn into one. Then send any request from it, or run the whole file as a suite from its folder's menu.

For RequestFox 2.5.0, checked 17 November 2026.

How do I move a collection from Postman?

  1. Export it from Postman

    In Postman, open Collections, then the collection's View more actions menu → More → Export collection, and save the JSON file. Postman writes Collection Format v2.1 [1]. RequestFox reads v2.0 and v2.1.

  2. Import it into RequestFox

    Open Compose, then Import → Import a collection…, and pick the file. A file on a web server works too: Import from URL….

  3. Read what it kept

    The note after the import says what came along, such as "Kept its variables (4) and its auth in Collection settings." and "Made checks (6) and chaining rows (2) from its tests, each on its own request.", then what was left out and why.

  4. Fill in what a file can't carry

    Each OAuth 2.0 sign-in in the file gets a button, “Add “My API” as a sign-in…” with its own name: press it and type the client secret, which the file doesn't hold. Pick files for form fields in Compose before you send.

  5. Send a request, or run them all

    Pick a request and press Send. To run the whole file with its checks, open the menu of its folder (or of one collection) in the saved collections and choose Run as a suite….

Which Postman tests come along?

The common ones become checks that need no code, so they run in Chrome, in Firefox and in the command line in CI: a test of the status, the response time, a header or a JSON field becomes a check on that request, and pm.environment.set("name", pm.response.json().path) becomes a chaining row that saves the value for the next request.

A test with anything else in it isn't run. The import lists it under "Scripts not translated", and the script stays on the request, so exporting to Postman gives it back as it was. To bring one over by hand, paste it into a RequestFox script box in Chrome: each pm. line is pointed out with its rf. twin, and one button fixes all of them.

What do I have to set up again?

  • Environments. A Postman environment is its own file [1], not part of the collection, and RequestFox doesn't read it. Make a RequestFox environment with the same variable names, or import a .env file with Import .env….
  • Variables with no value here. Postman variables the collection doesn't define are sent as written, and the import lists them: give each a value or an environment variable.
  • Files. A form field or a body that is a file can't come along in a collection file, and the import names those requests.
  • Old files. A Postman v1 file is refused with "This is a Postman v1 file. Export it from Postman as Collection v2.1."

Can I take it back to Postman?

Yes. A saved collection's Export… can write a Postman Collection v2.1 file, with the untranslated scripts as they came, and a folder's Export… writes the whole imported file back as one collection with its folders. It tells you what Postman can't run or read, like RequestFox's own checks and chaining rows. A recorded session also exports as a Postman collection from Export at the bottom of the panel.
